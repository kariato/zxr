# Generated Zork II data

`world.zxr.json`, `vocabulary.zxr.json`, `strings.zxr.json` and `memory.zxr.json` are generated from the unmodified MIT Zork II source at historicalsource/zork2 commit `3da9661098809788a99cef00f00c865c6c204f96`, vendored under `reference/zork2`. It retains the source game's MIT license; keep [ZORK-II-MIT.txt](ZORK-II-MIT.txt) with any distribution of this generated game data. Zork trademarks are not licensed by that notice.

Generate with `npm run world:record`; verify without writing with `npm run world:check`. Source locations in the JSON are relative to `reference/zork2/`. `reference/world-audit.json` records source hashes and comparisons against the release 63 / serial 860811 binary. `reference/world-spot-checks.json` records ten room and ten object source examples.

This is metadata-stage output: 86 rooms, 165 objects, 795 non-exit properties, 31 defaults and 220 encoded exit properties with byte-derived views. String words are zero placeholders with explicit text relocations; routine words hold stable ZXR IDs with relocation metadata for the oracle audit. The linked table/global/property/exit data is in `memory.zxr.json`; runtime execution and bundle packing remain later steps. Read the top-level stage tag before using it. Startup mutations from GO have not been applied.

`vocabulary.zxr.json` is vocabulary-stage output: 269 syntax rows in 135 lexical tables, 689 dictionary word roles, 148 action/preaction dispatch pairs, 18 prepositions, 75 synonym declarations, 38 buzz words and 14 directions. Generate with `npm run vocabulary:record`; verify with `npm run vocabulary:check`. `reference/vocabulary-audit.json` records exact assembly/binary comparisons. Syntax IDs are one-based within their lexical table; dictionary indices are not runtime addresses. Dictionary packing/allocation is in `memory.zxr.json`; JSON Schemas and bundle validation remain later steps.

`strings.zxr.json` contains 1,342 nonzero handles for decoded runtime text, shared across 1,589 source literal sites in routines/defaults, globals/tables, properties and exits. Word spellings, DECL/binding metadata and mutable object short names are excluded. Generate with `npm run operations:record`; verify with `npm run operations:check`. The operations-stage IR uses these handles; memory-backed uses are linked in `memory.zxr.json`.

The generator, independent audit and ZXR application code retain the repository's Apache-2.0 license. No GPL walkthrough data was used to generate these game artifacts.

`memory.zxr.json` contains the source-built, pre-GO big-endian data image and its allocation/field/relocation metadata: 19,882 bytes, 45 source tables, 251 object records and property tables, 689 packed dictionary entries, syntax/dispatch tables and 168 global initializers. Routine/string words contain ZXR IDs, not original packed addresses. Object short names use standard V3 encoding without abbreviations. `npm run memory:record` generates it and `reference/memory-audit.json`; `memory:check` verifies both against the pinned assembly/story. The guarded SRC-011 INDENTS normalization preserves the original binary's two-space alias; generic empty strings remain distinct. This is data for the future JSON engine, not an executable Z-machine story. The MIT source notice applies to these derived game facts and text.
