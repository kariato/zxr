# Zork II rules and differences ledger

The compatibility target is the pinned **release 63 / serial 860811** binary. Reference findings do not authorize gameplay changes. Keep `reference/zork2` unchanged.

| ID | Class | Evidence | Decision |
|---|---|---|---|
| REF-001 | Reference interpreter limitation | ifvms 1.1.6 remove_obj repairs parent/sibling membership but retains the removed object’s own sibling word. A three-object unit probe reproduces it; the unicorn refusal in TAKE ALL exposes it in game RAM. | Keep ZXR REMOVE clearing parent/sibling and retain strict tree validation. Normalize only detached sibling words in turn comparisons, with exact affected object names asserted per scenario. See docs/reference-audit.md; no vendored source, story or recorded oracle snapshots are changed. |
| SRC-001 | Source/build configuration | `gmain.zap` PERFORM contains the `PRSI=IT` guard from the PREDGEN variant in `gmain.zil`; its direct dispatch has no DD-APPLY wrapper. ZORK-NUMBER is 2 and Zork III-specific branches are absent. | Select the PREDGEN game-code variant and ZORK-NUMBER=2 for compatibility. |
| SRC-002 | Source/build metadata discrepancy | `zork2.zil` says `<ID 0>` when PREDGEN is assigned, but the supplied story identifies itself as release 63. The original build driver and command-line ID handling are unavailable. | Preserve the supplied story's release/serial and record the discrepancy. Do not label a future port's release-header difference as a gameplay bug or silently infer that PREDGEN was absent. |
| SRC-003 | Source inventory difference | The earlier line-based scan counted 441 routines and 24 I-* declarations. The phase 1 reader finds 456 routine forms including object comments/inactive branches, with all seventeen exclusions recorded in `reference/active-program.json`. `crufty.zil` is not inserted, and debug PERFORM/DD-APPLY is unselected. | Use the active manifest's 439 routines and 23 interrupts. Excluded source forms are not missing port routines. |
| SRC-004 | Permitted source redefinition | Shared `gverbs.zil` and game-specific `2actions.zil` both declare DUMMY. The entry sets local REDEFINE to true; assembly has one DUMMY slot with the game initializer. | Keep the later declaration and record the override. Reject duplicates when REDEFINE is false/unassigned. |
| SRC-005 | Source inventory correction | The reader finds 269 active syntax entries and 75 synonym forms; all syntax bytes and synonym dictionary roles match the assembly. The earlier 267/74 line counts missed forms nested inside compile-time conditions. | Use 269/75 as phase 2 vocabulary completion targets. |
| SRC-006 | Source/compiler interpretation | DREARY-ROOM-FCN's final `(T <PCHECK> <RFALSE>)` is outside its COND. The supplied assembly runs PCHECK/RFALSE as the fallback after the conditional look path. No general executable-list semantics were specified. | A Node-side normalization replaces exactly that trailing list with an unconditional PROG containing PCHECK/RFALSE. Guard the complete expanded routine hash and the assembly anchor; retain source spans and record the rule in the symbol manifest. Changed source fails until reviewed. The vendored source is unchanged; no claim about the unavailable original compiler's interpretation is made. |
| SRC-007 | Allocation specification correction | zork2dat.zap T?1 emits 180 word zeros for ITABLE NONE 180; T?13 emits 50 words for ITABLE NONE 50. C-TABLELEN=180 refers to the clock's used byte range. | Reserve 360 bytes for C-TABLE, 100 bytes per match table, and 200 for P-OCLAUSE. The phase 2.0 candidate's claim that NONE 180 meant 180 allocated bytes was wrong. Preserve source constructor units rather than inferring allocation from consuming code. |
| SRC-008 | Text normalization specification correction | Source LDESC/TEXT/FDESC line wrapping folds to spaces in `.GSTR` data. Vertical bars produce output newlines and suppress immediately following formatting newlines. All 175 metadata text properties match the original binary with this rule. | Use decodeZilText during world generation and later routine/string-pool translation. Preserve other spacing, explicit blank lines and indentation. The earlier candidate's “preserve other spaces/newlines” did not distinguish physical source line breaks from output newlines. |
| SRC-009 | Control-flow contract clarification | GO ends with an AGAIN outside an explicit PROG/REPEAT. `2dungeon.zap` ends its GO body with CALL MAIN-LOOP then JUMP ?FCN; ?FCN labels the first PUTB body instruction. | Lower routine-level AGAIN to the implicit routine-body target, retaining the current activation. Keep explicit block targets distinct; do not compile it as recursive GO or reject it as an unbound block jump. This fills an unspecified case in the draft; phase 3 still must execute and verify restart/default behavior. |
| SRC-010 | Memory-operation contract clarification | SYNTAX-CHECK uses `<REST .SYN>` without a count. In gparser.zap its GETB SYN,0 is followed by INC SYN, advancing one byte. | Normalize an omitted REST count to a literal 1; explicit REST/BACK counts remain byte counts. This adds one literal node to linked IR and preserves operand evaluation order. Execution evidence remains phase 3. |
| SRC-011 | Source/compiler interpretation | INDENTS begins with an empty string followed by two spaces in source. zork2dat.zap T?20 refers to STR?183 for both cells; zork2str.zap defines STR?183 as two spaces. Both original binary cells contain that same packed string pointer. | Normalize only the first INDENTS initializer to two spaces, guarded by the complete expanded GLOBAL hash, exact assembly anchors and pinned story hash. Preserve source spans and record the rule in the symbol manifest. Changed source fails until reviewed. General empty strings retain a nonzero handle, including V-PLAY. Vendored source remains unchanged. |
| SRC-012 | Address-boundary contract clarification | The shared image has adjacent allocations, so a preceding one-past pointer and following base can have the same 16-bit value. Numeric address equality cannot retain hidden provenance. | Bounds-check each complete access within an allocation whose closed pointer range contains the evaluated base. Shared endpoints can select the fitting preceding/following allocation; a word must never straddle them, and padding is never dereferenced. REST/BACK remain byte arithmetic with overflow/bounds checks. This clarifies the draft's ambiguous unconditional ban on dereferencing one-past values. |
| LANG-001 | Deliberate language scope | Zork II has fifteen DEFMACs and three DEFINE helpers. Seventeen definitions are selected; debug D-APPLY is unselected. TypeScript ports and definition guards cover all eighteen. | Defer a general MDL macro interpreter until a second game needs it. Reject unknown/altered macro programs rather than silently expanding by name. |
| REF-001 | Interpreter setting | Reference RNG is pinned MT19937/CPython integer seed 2; some death fixtures invoke the original `#random` verb. Restart and restore reset/restore reference RNG state. | Replay the logged ranges/results during conformance. Normal ZXR play may use its own owned RNG. Do not classify different normal RNG numbers as source-version differences. |
| REF-002 | Host setting | The headless runner suppresses the V3 status line and normalizes CR to LF; it keeps game text and prompt output. | Compare the recorded normal text. Rendering a status bar is a presenter concern. |
| ADAPT-001 | Parser replacement contract | Original parser checkpoints require counted matches, lexical ACT? identity, exact syntax bytes, continuation buffers and implicit TAKE effects. The new semantics probes retain twelve binary scenarios. | Replace input scanning/noun resolution with explicit options; keep the original prologue/MANY-CHECK/TAKE-CHECK, raw buffer overwrite behavior, pseudo activation and continuation timing. Do not preassign PRSO/PRSI or assume one pass per option. |
| ADAPT-002 | Input exclusions contract | AGAIN/OOPS/orphan input and #RANDOM/#COMMAND/#RECORD/#UNRECORD require typed input or stream protocols. DIRIN/DIROUT occur in compiled debug verbs. | Do not offer these options. Any reached unsupported stream operation errors explicitly. Numeric debug input is excluded; RANDOM 0 uses owned deterministic reseeding rather than external entropy. |
| ADAPT-003 | Spoken and pending input contract | RIDDLE-ROOM-FCN consumes P-LEXV at P-CONT/P-CONT+2; V-INCANT stores its first word. READ also occurs in FINISH and YES?. SAY HELLO can run a second pass. | Offer dictionary-backed quoted say actions, and correlated decision choices for nested READ. Preserve any continuation that the translated handler leaves live. |
| ADAPT-004 | Initial parser-buffer setup | GO reads P-LEXV for the initial capacity write. | Preserve startup setup before adapter input. |
| ADAPT-005 | Pending READ decisions | FINISH reads RESTART/RESTORE/QUIT; YES? reads YES/Y. | Offer correlated pending choices, fill the original buffers and resume the translated routine. No extra parser prompt or turn. |
| ADAPT-006 | Incantation word identity | V-INCANT reads P-LEXV at P-CONT and stores that dictionary address in SPELL-USED. | Dictionary-backed quoted say/incant options preserve the selected word, continuation and translated resets. |
| ADAPT-007 | SAY continuation | V-SAY delegates to INCANT for the wand/spell branch, otherwise checks HELLO and may leave a continuation. | Supply canonical quoted speech records, preserve handler cancellation and run another pass only when translated state leaves it live. |
| ADAPT-008 | Riddle speech | RIDDLE-ROOM-FCN tests WELL at P-CONT or P-CONT+2 for ANSWER/SAY, then clears continuation. | Offer quoted dictionary-backed say/answer sequences, preserving both tested word positions and ordinary wrong-answer responses. |
| ADAPT-009 | Actor continuation | V-TELL tests and may clear P-CONT. | Actor options keep the original TELL pass followed by the actor command only when continuation survives. |
| ADAPT-010 | Handler cancellation | All external P-CONT reset sites are enumerated in the generated parser ledger. | Keep these exact translated writes. The adapter must not pre-clear continuation or restore it after a handler cancels it. |
| ADAPT-011 | Structured action boundary | Pre-baked choices provide complete syntax/noun bindings; typed orphan/reserve input is already excluded by ADAPT-002. | Require an authored continuation for surviving multi-word quoted commands. Bare source directions and zero-object verbs can resolve directly. Reject ambiguous/mismatched identities, simultaneous multiplicity, nested speech/actor changes and unbound command scanning atomically; never silently choose another object or accept arbitrary text. Empty ALL and absent bound nouns retain original missing-match behavior. TurnLoop publishes the original next fresh READ; its internal execution packet/checkpoint is not the public session/save protocol. |
| HOST-001 | Host verification contract | VERIFY originally checks story checksum; ZXR executes validated JSON rather than that story. | VERIFY reports semantic-bundle validation. Never return success for a corrupt/unvalidated bundle. |
| HOST-002 | Checkpoint and transaction contract | Primitive SAVE is inside a translated call stack; exposed prompts and external disk effects cannot be rolled back. | Save complete continuations; restore the saved SAVE success branch. Use atomic execution segments through the last exposed boundary, including RNG/frames/gates. Keep committed prompts and completed host writes; replay records every host result and restore payload. |

The opcode audit has no differing routine headers, opcode sequences, or decoded instruction offsets. It is not a rebuild or exhaustive comparison of every operand, property table, or string in the source. Twenty source/assembly spot checks and their checked anchors are in `reference/spot-checks.json`; details and limits are in `docs/reference-audit.md`.

[Parser split evidence](parser-ledger.md) lists every one of the 42 parser classifications, all 32 external P-LEXV/P-CONT access sites with its rule and planned handling, and all three READ sites. `npm run parser:check` verifies this generated evidence. Retained helpers execute only inside action/adapter transactions; options queries cannot execute translated routines. Runtime adapter/decision conformance remains phase 3.
