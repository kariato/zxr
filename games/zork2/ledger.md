## Fix-or-ledger review (5.2, 2026-10-23)

All 35 entries above were reviewed against the compiler/engine contracts and the complete 75-script conformance evidence. The duplicate REF-001 identifier was corrected: REF-001 continues to mean the ifvms REMOVE defect; the reference RNG setting is now REF-003. Existing references to the REMOVE decision keep their meaning.

- SRC-001–SRC-012 and LANG-001 retain their recorded source/configuration/allocation/translation decisions. The original source, binary and frozen goldens are unchanged. Stale pre-implementation wording for SRC-009/010 is updated to the execution evidence now available.
- SRC-013 retains the authored empty V-PLAY death message. The compiled binary's unrelated “Pushing the ” fragment is a string-alias discrepancy. A fresh binary replay, the source/assembly anchors and the compiled IR empty-string argument establish the cause. Its sole exception compares both complete texts for one command/input; no game state or random result is waived.
- REF-001 retains exact detached-sibling normalization and strict engine tree validation. REF-002 retains presentation-only CR/status-line settings. REF-003 and RNG-001 preserve the explicit distinction between reference tape replay and native seeded execution.
- ADAPT-001–ADAPT-015 retain the structured-input contracts, exact raw-input bridge and query-only presentation policies. The phase 5.1 operand-adjective and cancelled-actor fixture errors are fixed in authoring, not accepted as game-rule differences. Numeric debug and invalid FINISH coverage remains diagnostic-only.
- HOST-001/002 retain validated-bundle VERIFY and complete transactional save/host continuation rules, backed by lifecycle and conformance tests.

`reference/conformance-review.json` records the ledger/policy/evidence hashes, unique IDs, reviewed adaptation counts, source hashes and pinned story hash. The conformance CLI validates this review before replaying the corpus. Adding, widening or relabelling a text exception, using an unknown adaptation kind, or changing reviewed evidence fails until explicitly reviewed and recorded. `npm run conformance-review:check` verifies the review; `npm run conformance-review:record` deliberately updates it after review.

Phase 5.5 extends this review to 36 decisions with SRC-014. The original source and assembly both pass a byte count to a helper requiring an inclusive word index. The existing WORD-IN-SYNONYM implementation establishes the intended `PTSIZE / 2 - 1` bound. A complete-routine hash and assembly/story anchors constrain the correction to V-CLIMB-UP. The pinned binary's refusal and move count are retained by the regression; general allocation semantics and the sole SRC-013 conformance-text policy remain unchanged. ADAPT-002's already recorded numeric/stream exclusions are now enforced in public session candidates; the full static syntax audit remains intact. ADAPT-009 also retains the original player WINNER when a direct-object handler intercepts TELL but leaves P-CONT live (distant unicorn); the original binary then executes the remaining command as the player. No native reassignment or cancellation is introduced.
