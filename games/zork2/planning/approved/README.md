# Approved planning assets

`manifest.json` selects the approved scene plans, asset briefs and label sets used by an offline build. Mark approved the current review set in this chat on 2026-10-23. The manifest now selects **22 exact approved records: eight room plans, eleven asset briefs and three label sets**. Each immutable record preserves its input identity, output hash, reviewer and date. The original draft files remain for comparison. The approved files and manifest are ready to commit together.

The default workflow uses Codex in the current chat to author JSON, without an API key. Prepare context with `npm run planner -- prepare KIND SUBJECT`, then validate the assistant-authored JSON with `npm run planner -- import KIND SUBJECT FILE`. The current [pilot review set](../drafts/README.md) is approved; future additions and revisions still require review. Inspect a draft, then explicitly approve it with `npm run planner -- approve DRAFT --reviewer NAME`. Only run approval after the named reviewer has approved that exact document. Commit the selected record and updated manifest together. Existing approvals require `--replace` to select a new revision; historical files are retained.

`npm run planner:check` and production builds validate selected records against current source, prompt, schema, model, style and image inputs. Stale or edited selected records fail rather than silently falling back. The build never calls a model or reads `out/planner/cache`. Requests, import scratch files and the disposable cache stay under ignored `out/planner/`. Tracked pilot draft originals remain in `planning/drafts/` for comparison; their presence never selects approval.

This approval covers the current planning documents, not future additions or actual generated GLB geometry, animations, occlusion or device acceptance. Schema validation is not human art approval. The editing/field-lock review page belongs to step 6.7; direct edits to a record invalidate its output hash.
