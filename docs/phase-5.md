## Conformance runner (5.1)

`node bin/zxr.ts check --conformance` compiles the pinned Zork II source and checks every script in `reference/scripts/fixtures.json` against its frozen `reference/transcripts/*.json.gz` oracle record. CI runs the command explicitly. Missing scripts, changed command lists, altered original or normalized identities, missing authored inputs and changed detached-sibling dispositions fail. `npm run conformance:check` is the same command. `npm run conformance:record` deliberately authors and checks new fixtures before replacing the two generated records; the normal check never records or weakens expectations.

`reference/conformance-inputs.json` contains explicit structured actions, decision choices, diagnostic numeric inputs and the single invalid FINISH reply. The authoring helper reads each operand's own source parser clause, so an adjective belonging to one operand cannot leak into another. The runtime does not acquire a typed-command parser. Diagnostic capabilities let the development runner execute the original `#RANDOM` handler with its explicit number and exercise the original FINISH rejection of `nonsense`; neither input is accepted by the player/session API.

The runner compares the typed semantic projection from `compat-semantics.md` at parser return, completion of `MAIN-LOOP-1` after the clock, each exposed READ, and terminal/victory boundaries. Parser-return capture happens after storing the parser result in `P-WON`, matching the original VM's call-return store timing. Bounded diagnostics capture owned world snapshots only when the conformance runner requests them; they are outside saves and semantic hashes. Excess diagnostic snapshots are counted and dropped without changing execution; the conformance checker rejects a truncated capture.

Parser checkpoints additionally compare direct/indirect match lists, syntax bytes, continuation/quote state, lexical table and preposition numbers, active operand dictionary words and clause offsets. Preposition aliases compare by their source preposition identity, because the engine emits canonical source spellings. A direction has no active object syntax: its stale syntax/input record is omitted from this protocol view, while gameplay globals (including PRSA, PRSO, PRSI and P-WALK-DIR) remain compared. Unrelated stale buffer tails retain the existing contract's exclusion; full bytes still survive saves and execution.

Every positive game random request must match the original range/result and routine order. Reseeds are also requests. Parser draws remain marked in the original record, are counted explicitly and are omitted from engine tapes. A successful RESTORE rewinds to the saved tape cursor; RESTART begins a new tape at cursor zero. Internal and exposed checkpoints compare the corresponding cursor; missing requests, incompatible restored tape slots and unused tails fail. No native RNG fallback is allowed.

SAVE/RESTORE requests resume the actual saved success continuation or the source failure branch. Restart runs fresh GO. QUIT is checked at the terminal host boundary. These are deterministic development host operations, not disk or browser-storage tests; those remain covered separately and are extended in 5.3.

Existing raw-input dispositions remain explicit: period-separated commands become separate choices, and the two reviewed no-action parser inputs are excluded with the exact bridge checks from phase 3. An actor ID has no noun-alias field; the GENIE actor prefix uses its first source synonym, DEVIL. Conformance therefore normalizes DEMON prefixes to DEVIL before obtaining the structured counterpart from the original binary, records each changed input, and bridges its text/state back to the frozen original. No gameplay projection fields are excluded for this normalization.

One complete-text exception is recorded under **SRC-013**: the original V-PLAY binary passes the “Pushing the ” string to JIGS-UP where the source supplies an empty string. `reference/conformance-differences.json` binds the exact full original and engine texts to `death-8b33`, zero-based input 38 and `play robot`. Both full texts must match, the expected exception must be exercised, and all state/RNG checks remain strict. This follows SRC-011's existing policy to preserve general empty source strings. It is a documented source/binary text difference, not a substring ignored by the checker. The decision was confirmed by the step 5.2 fix-or-ledger review below.

A failure names the script, one-based structured turn, original input number, command and first differing text character or semantic field. Execution and misaligned RNG failures report the actual ZIL expression. Internal state/parser failures report their checkpoint site; exposed text/state failures report the last executed site, not a claim to have identified the faulty writer. Source snapshots and expected texts are never printed wholesale on a normal successful run.

Mutation tests corrupt a flag, clock entry, property string, object location, PICK-ONE counter, message ordering, table interior pointer and ordinary gameplay word. Each fails at its first affected checkpoint. A separate mutation of a parser match list fails before gameplay can overwrite it; a wrong random range fails at the first request and reports its ZIL site. Missing inputs and mismatched oracle identities/dispositions also fail.

## Persistent saves (5.3)

The browser now keeps the latest ordinary input boundary in IndexedDB and tries to restore it when **Start Zork II** is selected after a page reload. Accepted actions, decision returns, successful imports and host completions update it only when the resulting session is at an ordinary input boundary. Browsing choices and editing a checkpoint name do not write an autosave. Pending decisions, suspended host requests and terminal games retain the last ordinary autosave. An initial new game gets an autosave too.

**Saved games** provides named checkpoint save/load/delete and an explicit **Load autosave** button. An empty name generates a local date/time name; names are trimmed, limited to 100 printable characters, displayed as text and encoded for storage. Saving an existing name replaces that checkpoint. The name field is metadata, not a game command box. Saves do not contain transcript history; restoring a boundary does not replay the opening or spend a LOOK turn.

`src/persistence/saves.ts` stores the existing `zxr-save-v2` envelope directly. It namespaces slots by semantic build hash and separates `auto`, `named:<name>` and `source` records. Autosave/named slots require boundary checkpoints; the source slot requires a primitive SAVE checkpoint. File import/export remains portable JSON with a 32 MiB limit. Storage parsing checks schema, build, ABI and slot kind; `GameSession.importSave` performs the full memory, continuation, RNG and knowledge validation before atomically replacing a live game. Failed imports preserve live state. Successful loads retain identical semantic state and establish a new epoch relative to the receiving session; epoch/revision are local protocol metadata, not global IDs across browser processes.

Source SAVE waits for the IndexedDB transaction to commit before reporting success to its suspended continuation. RESTORE loads that primitive checkpoint and resumes its saved SAVE success branch. The old browser `localStorage` source slot is migrated lazily on RESTORE when the new source slot is empty; its bytes are preserved. Autosaves and named checkpoints never replace the source SAVE slot. The terminal player's synchronous file store continues to use the same engine host protocol.

The asynchronous host adapter captures the request identity before storage yields and checks its ID, kind, epoch and revision against the live session before acknowledging it. Late and duplicate completions cannot consume a newer request. Aborted writes fail the original source SAVE; failed RESTORE resumes the source failure branch. Browser actions are disabled while persistence is pending, preventing overlapping UI operations.

The IndexedDB text store and timestamp helper adapt the generic utilities from rougeXR commit `820cb92500226f5e8817c9a4a452651d94a7609c`, pinned in phase 0. The Rogue save codec is not reused. Ordered writes resolve on transaction completion, reads wait for queued writes, and a rejected transaction does not poison subsequent writes. Database open failures can be retried. The BSD-2-Clause copyright/license is retained beside the adapted sources and copied into `dist/licenses` by the build.

Storage failures are visible and leave the live game and file import/export usable. A corrupt or incompatible startup autosave is reported and left untouched; importing a valid file or committing a later ordinary action can replace it. Storage is local to the browser origin/profile; separate tabs use the latest completed write, with no cross-tab merge or lock. Named checkpoints and exported files let the player preserve alternatives.

## Replay bundles and playback (5.4)

**Export replay** records the current browser game. Open **Replay**, import the JSON file, then use **Step replay**, **Play replay**, **Pause replay**, **Restart replay** and **Replay speed** (0.5×, 1×, 2× or 4×). The viewer has its own transcript and deterministic engine session. It performs no host storage operations and never changes the live game, its recorder or its autosave. Playback stops automatically at the end or at its first divergence; restart begins again from the bundle's recorded origin.

The versioned `zxr-replay-v1` envelope contains the semantic build hash, gameplay ABI, an initial state hash and ordered frames. The origin is either an explicit native RNG seed plus execution limits or a complete starting ZXR save. A recovered browser autosave starts a new recording from that checkpoint, so replay does not require the previous page's history. The optional pinned random tape supports reference/oracle recordings; normal browser recordings use the seed and saved RNG state. Oracle saves require their matching tape and cannot silently fall back to native random draws.

Each frame owns an accepted input and its resulting semantic state hash. Staged selections retain the exact chosen option ID and source-spelling operands, including actors, multiple objects, ALL and selected vocabulary words. Decision frames retain their chosen decision option IDs. Host frames retain the operation/outcome and embed successful RESTORE bytes; file imports retain the complete save and its hash. Browsing and editing checkpoint names do not add frames. Ordinary trusted-catalogue `execute` inputs are deliberately unsupported in portable bundles: player actions replay through the same scope-backed staged selection API used by the live player, without decoding an arbitrary action ID into executable input.

Playback reconstructs a fresh session and rebinds recorded epoch/revision, host IDs and decision IDs to that session. It checks the actual accepted input against the recorded input after this transport rebinding, including selection option IDs and embedded save hashes, then verifies the semantic hash before publishing that step's text. A bad choice, mismatched host operation, rejected save or differing hash freezes playback and reports the one-based input number plus expected/actual hashes. Input zero identifies an incompatible starting state. Host completions and decisions have their own frames, so verification also covers those intermediate protocol boundaries rather than only clock-spending actions.

The recorder captures immediately after each accepted live input and again after host completion. It refuses to invent intermediate hashes if the caller misses an input boundary. `acceptedInputs(from)` returns an owned log suffix for incremental recording and verification, avoiding a copy of the complete growing history on every input; calling it without an argument preserves the existing full-log API. Recording failures are reported without interrupting live play.

`schema/replay.schema.json` publishes the strict envelope schema and is generated/checked alongside the save schema, with independent AJV 2020 validation. The save schema's display title now correctly says v2; its contract is unchanged. Replay files are limited to 32 MiB in the browser and 100,000 input frames in the schema. Wrong build/ABI, unknown properties, malformed inputs and incompatible starting saves are rejected.

## Deterministic fuzzing (5.5, acceptance still open)

`npm run fuzz -- --games 2 --turns 16` runs the short CI smoke test. The default full command uses 10,000 games with a 300-player-input cap per game. A naturally terminal game stops rather than inventing choices after QUIT. Results report actual accepted inputs and terminal counts separately from the maximum input budget; a short smoke test is never described as three million exercised inputs. `--seed`, `--start`, `--games`, `--turns`, `--shard` and `--shards` reproduce and partition runs. `--bundle` reuses a validated compiled game. The chooser samples exits, per-object actions, general actions and always-available actions, across primary and More entries. It builds operands from the actual staged choices and source spellings, including ALL, compatible multiple objects and one to three selected vocabulary words from all 681 selectable entries, traversing every offered dictionary page. It selects offered decision IDs and correlates SAVE/RESTORE/RESTART/QUIT completions with success, failure or cancellation as the protocol permits. Successful SAVE payloads are retained for later RESTORE; storage is an in-memory host effect. It does not execute handlers to discover which actions will succeed. Actor selection is available when actors are offered; the smoke results do not claim to have reached actors or every puzzle.

Every accepted boundary is checked through the test-only `validateSessionState` capability: complete continuation, RNG and world memory restoration, knowledge and remembered-object validation. The **Full deterministic fuzz campaign** workflow runs on main pushes, pull requests and manual dispatch. Missing, duplicate, partial or mismatched results cannot certify a campaign. Superseded runs on the same branch are cancelled. The ordinary Check workflow also runs a short smoke test. `npm run fuzz:keys` shuffles object keys recursively while preserving arrays. ### Findings

The first failure was an offered FOOTPAD operand whose only source noun also names SAILOR. The source parser cannot uniquely resolve that spelling. The player now uses a pure counterpart of its room/inventory/global noun search, syntax-location retry and pseudo lookup to filter unresolvable spellings before offering them. FOOTPAD is removed when it has no unique spelling, while SAILOR retains its unambiguous aliases. Remembered missing nouns still retain the existing source NOT-HERE behavior. Matcher caches are confined to a session revision; lexical spelling data are immutable. Different pseudo features sharing the source proxy cannot be selected together. No handler probes or memory-bound changes are used.

The CLIMB failure is preserved historically in `reference/fuzz/seed-5920850-game-2.json` and minimized in `reference/fuzz/climb-down-self.json`. In V-CLIMB-UP, `gverbs.zil:340–341` passes `PTSIZE` in bytes as ZMEMQ's inclusive word index; the assembly repeats this mistake. **SRC-014** normalizes exactly that bound to `PTSIZE / 2 - 1`, matching the existing WORD-IN-SYNONYM routine. The correction is guarded by the expanded routine hash, assembly anchor and pinned story hash, with source spans and normalization provenance retained. Changed source fails until reviewed. The vendored source and general allocation bounds are unchanged. The regression now expects a resolved action with the original `You can't do that!` refusal and move 1. This deliberately removes undefined adjacent-memory reads; it adds no conformance tolerance. The corrected game has a new semantic build hash, so older game-build saves remain incompatible as designed.

Continuing the same native seed reached input 233 and exposed `$VERIFY:1`: menus offered the source lexical table, but both selection and action schemas rejected the dollar sign. Selection requests now accept its name, and the action lexical-table schema explicitly admits `$VERIFY` alongside ordinary names. Exact catalogue/syntax checks still apply; unsupported numeric/stream debug commands remain excluded. Numeric and stream debug families (`#RANDOM`, `#COMMAND`, `#RECORD`, `#UNRECORD`) also appeared in menus despite ADAPT-002 excluding them. They are now removed at the public session boundary, with direct unsupported drafts still rejected atomically; the static 269-row audit remains complete. A fresh-menu regression resolves VERIFY and checks its successful validated-bundle response. `reference/fuzz/verify-family.json` records the minimized case.

The same native game next exposed a visible `GLOBAL-UNICORN` actor menu in GARDEN-NORTH. That proxy lives in LOCAL-GLOBALS, so META-LOC returns GLOBAL-OBJECTS rather than a room. Actor scope now uses the containing room only when it is a real room, otherwise the current HERE. META-LOC itself is unchanged. The actor prefix is also checked with the pure source noun matcher: once the real unicorn is present, the proxy prefix resolves to that real animal, so only the real actor remains offered. A controlled valid-save regression builds the offered actor menu and commits its wait action, retaining the translated `Unicorn? What unicorn?` refusal. The binary then executes WAIT as the player because the intercepting handler leaves P-CONT live without changing WINNER. The adapter now permits that retained player context while keeping the continuation offset/quote checks. An independent original-binary comparison checks the full output (including `Time passes...`), moves, winner, state and RNG. See `reference/fuzz/global-actor-room.json`.

The offered-action checker now requests only RANDOM trace operations, which are the source sites it actually compares. Filtered traces identify their operation filter and retain normal fault stacks; default traces remain complete and bounded. A fixture verifies identical output, RNG and checkpoints against a full trace. This avoids copying entire unrelated execution traces during the long regression. The full walkthrough selection test has a 300-second budget. The replay integration test has a 900-second budget, matching the offered-action acceptance test: it records the solve, then plays the whole solve and the saved second half with hashes at every input. This accommodates the complete menu-resolution workload on two-core CI runners; assertions, action counts and per-input checks are unchanged.

A validated property-size index avoids rescanning every object for every noun lookup. Raw writes to headers, lengths, terminators or property pointers mark the layout dirty and retain the original full memory scan until validation succeeds again; forks preserve that dirty state. Tests cover cached data writes, invalid header writes, dirty forks and recovery, so the optimization preserves structural fault detection.
