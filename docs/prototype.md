# Playable 3D prototype

Mark's 2026-10-24 direction prioritizes a working adaptation of Zork II over finishing the authoring editor and reviewing all proposed assets. The original game supplies the rules, puzzles, prose, turns and progression. The translated engine and presentation still need testing: the original game's maturity does not automatically verify our port.

Run `npm run dev -- --port 5181 --strictPort`, open the root page and choose **Start Zork II**. The 3D view and text player share one session, command controller, transcript, save/restore path and replay recorder. Existing autosaves are restored; if they place the player outside the slice, use the source Restart action through the text menu to begin again.

- **Three modeled rooms:** Inside the Barrow, Narrow Tunnel, Foot Bridge. Rough procedural shells, a flat sword and an unlit/lit lamp establish the playable loop, not finished environment art or exported GLBs. The tunnel shell is intentionally simplified; it does not reproduce every approved-plan dimension or ravine detail.
- **Desktop:** drag the scene to look; focus it and use WASD or arrows to walk locally. Click a sword/lamp to open its source actions below the scene. Choose the action and finish the sentence. Click a doorway label or a movement button for one source movement attempt. Failed movement stays in the source room and still spends the source-prescribed turn. Walking locally never changes rooms or spends turns.
- **Touch:** drag to look, hold directional buttons to walk, tap props and source action buttons. The same commands work without a keyboard.
- **VR:** on a secure origin and a WebXR-capable browser, the VR button requests an immersive session. Point a tracked controller and press the trigger to select props, doorway labels or the floating command panel. The panel mirrors source action choices with paging, Finish and Cancel, and paged source output. Room changes are discrete source transitions. Use the desktop word picker for vocabulary inputs in this first prototype. No microphone or speech recognition is requested.
- **Scope:** only current visible sword/lamp observations become props, with directly held props attached to the view. Taken/dropped props and lamp light update after source actions. Darkness removes all room geometry. Other visible objects and rooms remain playable through text and source menus; they do not acquire guessed geometry. No neighboring destination is preloaded or disclosed by movement-attempt buttons.

The three physical route labels are hand-authored for these known unconditional source routes. Other source directions remain available as attempts. This is not the combined-room GLB loader, continuous boundary crossing, full object placement/occlusion system, character animation, TTS audio or final collision system. Desktop walk bounds prevent leaving the simple floor; headset physical movement is not artificially clamped. Real-headset usability and performance measurements are still required before calling this device acceptance.

The implementation is in `src/prototype/`. It consumes filtered observations, not engine debug APIs or the full offline authoring context. Shared controller methods browse a scoped object menu or commit a currently offered movement draft. All spatial actions pass through the browser's existing busy guard, host operations, recording and autosaves. WebGL failure leaves the text player available. Hiding the scene pauses desktop rendering; the prototype also provides teardown for textures, meshes, animation loop and renderer.

Automated tests cover turn-free spatial browsing, take/drop observation changes, source-controlled movement/refusal through the three rooms, save restoration, and hidden/contained/dark-room filtering. Headset, touch hardware and visual-art acceptance remain manual checks.

Verification on 2026-10-24: all **764 unit tests across 63 files** passed, including 21 focused controller/appearance/prototype tests. Type checking, headless boundaries and the production build passed. Browser verification clicked the rendered sword, selected pickup and finished it for one turn; traversed the barrow → tunnel → bridge and back; switched on the lamp through its offered action (including the source's implicit take); restored the session after reload; and used the source Restart/Yes flow to return to a fresh barrow. The console reported no warnings or errors during these checks. At a 768×1024 viewport the page had no horizontal overflow. The browser reports VR NOT SUPPORTED, so this is no claim of actual headset or touch-hardware acceptance. The screenshot is retained under ignored `out/prototype/barrow.png`.
