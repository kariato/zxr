# Action plans (step 3.4a)

Player input uses predefined text choices for non-movement actions, mapped to structured option IDs. There is no microphone input, speech recognition or speech-to-text. References below to say/speech describe the game’s internal quoted-word semantics; those words come from the selected authored choice. Character audio is generated separately with local Python TTS on the Mac mini.

`prepareAction(game, world, action)` prepares owned, deterministic lexical data for a structured action. It is pure: it reads definitions and the current world, but never runs translated routines, activates pseudo features, consumes randomness or writes parser state. The completed step 3.4 consumes plans through the integrated TurnLoop described in 3.4o. Planning alone is not execution or option availability.

Supported shapes are the design's `act`, `walk` and quoted `say`. PLAYER resolves through the current PLAYER global; other actor names identify source objects with ACTORBIT. Non-walk actions require the exact lexical table, one-based row and matching action name. The row must be the first matching object-count/preposition pattern in emitted syntax-table order. Operand counts must match the row. Unknown keys, invalid references, duplicate operands, two-sided multiplicity and different pseudo features sharing PSEUDO-OBJECT fail explicitly.

Plans include semantic build identity, an action ID encoding every supplied field in canonical JSON, the allocated syntax address/action, symbolic selections, lexical noun spans, canonical input records and quoted-speech continuation positions. Caller mutation cannot change a prepared plan. The ID is paired with the build hash; it does not supply the later epoch/revision protocol or authorize execution.

`ALL` remains an unresolved selection. Explicit lists retain their supplied order as input data; the runtime resolver must produce reference search order before filling match tables. Pseudo bindings identify the room, word and handler without modifying the shared object's name/action. Actor prefixes encode the comma input; the later adapter must perform the original COMMA-to-THEN rewrite and conditional TELL continuation. Speech records describe input before PARSER changes the count. These are not parser-return snapshots.

String operands use the entity's first source synonym; an explicit operand such as `{object: 'GOLD-KEY', noun: 'KEY', adjective: 'GOLD'}` chooses a source synonym and optional source adjective. Pseudo operands use the declared feature word. Planning validates these lexical declarations without proving uniqueness, visibility, reachability or a legal action in the current room. Translated scope helpers still validate the selected object's identity. Options must never treat a plan as proof that a hidden or remote object is available.

`encodeReadText()` implements V3 input tokenization with the source's period/comma/quote separators. Dictionary lookup compares four encoded bytes, preserving the original six-z-character significance, punctuation encodings and unknown-word zero. Tokens retain original lengths and one-based byte offsets. `writeReadText()` validates capacities/overlap and writes into a fork: lowercase text and its terminator, word count and emitted records. Unused text/parse tails and both capacity bytes remain intact. One-word decision handling delegates to this same implementation.

Ten tests cover syntax addresses and matches against original parser checkpoints, quoted continuation globals, metadata/actor/pseudo validation, ALL and multiplicity representation, stable owned IDs, independent ifvms tokenization, buffer-tail retention and atomic capacity failures. The original tokenizer receives the source-built dictionary image; addresses therefore compare directly without relocating expected values.

Step 3.4 is complete for the structured action language described here, including source-derived entry/check programs, nested scope and execution through the next fresh READ. Simultaneous multiplicity, orphan/reserve input and arbitrary unbound multi-word command scanning are explicit exclusions. The public session protocol remains 3.7; options and filtered observations remain phase 4.

## Retained source and limited execution (3.4b)

Bundles now carry source-derived parser `entry` and `checks` programs under adapter ABI `zxr-adapter-v15`; recompile older `.zxb` files. Entry keeps the original locals, ten-word table copy/reset loop, context reset and fresh/continuation arms. The unsupported reserve arm is omitted and rejected before entry. Checks retain the original short-circuit MANY-CHECK/TAKE-CHECK order and truth normalization, removing only SYNTAX-CHECK/SNARF-OBJECTS. Separate noVerb and notHere fragments retain the first rejection in SYNTAX-CHECK and the exhausted-search arm of GET-OBJECT; both complete routines remain excluded. Their source sites keep replaced-middle policy; entry/check sites keep adapter policy. The ordinary routine map still excludes PARSER and all removed scanner IDs.

`Interpreter.executeAction()` accepts ordinary PLAYER syntax rows with zero, one or two operand slots, including ALL and one-sided explicit lists, plus directional walk. `executeSimpleAction()` remains a compatibility alias. It accepts quoted PLAYER and actor ANSWER/SAY/INCANT through kind say; actor commands use the TELL pass below. Speech verbs encoded as act remain rejected. Surviving quoted continuations are bounded to the cases described in 3.4j–l. Pseudo operands must name a source feature in the current room. Simultaneous multiplicity remains rejected. Global/local-global fallback executes the retained GLOBAL-CHECK helper. Nouns use a source synonym with an optional source adjective; unresolved ambiguity still fails atomically. It executes the retained entry internally, fills READ records and parser fields, runs translated checks, and resumes MAIN-LOOP-1. PERFORM and CLOCKER remain translated code. Each fresh action starts its own step/output budget, while RNG state persists; any segment error restores the prior world, RNG, frames, budgets and output. Retained parser execution programs are explicit in frame checkpoints.

Scope executes translated DO-SL/SEARCH-LIST/THIS-IT? with the original room/inventory order, indirect clause first, lit-room PLAYER transparency toggle, and slot-bit retry on ambiguity. Open/transparent containers and searchable surfaces retain source traversal semantics. Search helpers populate the original direct/indirect match tables, preserving unused tails and retry writes. Parser fields include both match tables, preposition numbers/dictionary words and both noun spans. The scope controller is transaction-local and cannot be checkpointed or exposed at a host suspension. Adapter ABI v15 retains the widened execution policy, GLOBAL-CHECK helper, pseudo validation, quoted speech continuations, actor passes and explicit noun/adjective handling into build/checkpoint identity.

This is an internal integration API, without option availability, correlated epoch/revision IDs or public ActionResolution wrapping. Its output includes the fresh parser prompt before the action, since the current low-level boundary is just before PARSER. Tests compare this with the original stream by accounting explicitly for that prompt placement. TurnLoop now publishes the retained prologue/READ before accepting its next action (3.4o).

A five-command TAKE/DROP/LOOK/south/north sequence matches original output, room/move counts, input-table words and selected parser globals using the original random tape. Checkpoints round-trip after every command. Separate tests cover retained source projection, startup READ memory, actor/quote context, table-tail preservation, MANY refusal, implicit taking, unsupported reserve state and complete error rollback. ## Quoted PLAYER speech (3.4e)

`kind:say` now executes canonical quoted ANSWER, SAY and INCANT data. The adapter writes the original quote flag, P-CONT word index, P-LEN and remaining P-LEXV count at the opening quote, preserving all token addresses, byte lengths/offsets and unused records. Unknown dictionary words remain zero inside the data. Translated room/actor/object handlers and verb routines consume the words, cancel continuation and delegate SAY to INCANT when SPELL-USED or WAND-ON requires it. The native adapter does not interpret riddle answers or spell effects.

If translated SAY leaves a single HELLO pending, the adapter executes the retained continuation entry without a new READ, keeps the original token's byte offset in P-VTBL, processes the terminal quote state and dispatches the original HELLO syntax/checks/verb. The original two MAIN-LOOP-1/CLOCKER iterations are preserved: in the barrow SAY "HELLO" consumes two moves. Step/output limits and rollback span both passes; RNG state is not reset. If a handler consumes HELLO (for example the riddle's HELLO WELL answer, an actor-present refusal or wand delegation), its cancellation prevents this continuation.

## Actor act/walk commands (3.4f)

A non-player actor now uses the original two-pass flow. The first retained entry reads the complete canonical `robot, ...` input. The adapter rewrites the comma's dictionary record to THEN while retaining its original byte length/offset, fills the implicit TELL syntax and actor noun span, keeps P-VERBN zero and preserves the previous P-VTBL, and sets the original quote/remaining-count/continuation fields. Ordinary scope helpers validate the actor; translated checks, MAIN-LOOP-1, object handlers and V-TELL run. Only translated V-TELL assigns WINNER and HERE for an accepted command.

At the next parser call, an accepted TELL continues through the retained P-CONT entry without another READ. The adapter supplies the planned act/walk syntax with the original prefixed noun pointers and verb offset. Source quote state preserves the actor during entry, then the completed command clears the quote flag as the original scanner does. The same scope helpers, checks, PERFORM and CLOCKER execute. TELL is exempt from CLOCKER; the requested robot command normally consumes one move. A handler such as the unicorn's HELLO? may cancel TELL and the continuation, in which case the requested action does not execute and no TELL clock tick is added.

The current low-level API publishes just before the next PARSER call. Its world therefore matches the original actor action-complete checkpoint, which may still have WINNER/HERE referring to the actor. The next fresh retained entry restores PLAYER, META-LOC/HERE and LIT exactly as source code specifies; no native reset is inserted. The cage rescue handler itself switches WINNER back to the adventurer and performs GOTO. TurnLoop now runs the fresh prologue/READ before accepting its next action (3.4o).

Prepared-context oracle sequences cover robot movement, GIVE and robot TAKE/DROP, explicit inventory lists, refusal of LOOK, following the robot through rooms, the player's sphere trap and `robot, raise cage` rescue, then player LOOK. Checkpoints restore after every command. Missing operands, remote/invisible actors and execution budgets roll back both passes and their parser/global/RNG mutations.

Unexpected unbound continuations fail atomically. Once TELL has handed control to the requested command, the actor controller is released so the translated command can expose a decision or host primitive normally. ## Integrated turn execution and 3.4 acceptance (3.4o)

TurnLoop is the internal headless coordinator above Interpreter. `start()` runs the translated opening through fresh READ, returning its prompt once. `execute(action)` accepts a validated structured action at that boundary, runs all source passes and publishes only the next input, decision, host or returned boundary. TurnResolution contains actionSequence, status, text chunks, clockTicks, moves, random events and boundary/error details. It is the execution portion of the public ActionResolution planned for the session layer; it does not expose a public options/observation/save protocol.

The integrated Interpreter uses `inputBoundary: 'read'`; the original pre-PARSER mode remains the diagnostic default for existing oracle probes. The new mode runs the next fresh entry inside the same atomic segment, preserving the source's context reset, table-copy/count clearing and prompt placement. No source prompt is shifted to the following chosen action. A checkpoint records the mode. Integrated READs accept only executeAction; resumeParserRead is restricted to standalone diagnostic fragments.

TurnLoop diagnostic checkpoints include startup/sequence metadata and the complete validated interpreter checkpoint. Restoration requires the read boundary policy and original startup continuation. They are not external save envelopes. Malformed actions and input at the wrong boundary return rejected with no changes; runtime/budget failures return error and restore the full segment, including any next-prologue writes/output. start cannot repeat an opening. An accepted fresh action advances the sequence once; decisions and primitive completions keep that sequence and command budget. clockTicks measures the current returned segment, so resuming a decision cannot report an already committed speech tick twice.

`answer()` and `resumePrimitive()` are internal continuations for the later session protocol to correlate. SAVE success/failure and failed RESTORE/RESTART resume source code; successful session replacement and QUIT acknowledgment still belong to 3.7. Ordinary actions are rejected during these waits. These methods perform no host I/O and do not generate protocol IDs, knowledge gates or presentation events.

Exhausting ALL's local and global searches now uses the same source missing-match arm as explicit nouns. Original MAIN-LOOP-1 then supplies its own ALL/missing-object summary; no TypeScript message is invented. Surviving bare quoted directions, including dictionary aliases, use the original movement fast path: no syntax/check lookup, no overwritten SAY verb record, no consumed closing quote, and the exact remaining lexical count. A bound continuation may also be a canonical PLAYER walk. Simultaneous multiplicity, omitted noun phrases, unresolved ambiguity, reserve/repeat/correction controls, numeric/debug/stream input and arbitrary unbound multi-word continuations remain explicit language/capability exclusions, recorded in the rules ledger. They are not an unimplemented text parser promised by the options API.

The integrated acceptance tests compare complete output through fresh READ (without prompt slicing), source move/tick timing, player/vehicle context, both input tables, full match-table tails, exact syntax bytes, spelling fields, object links/flags, clocks and RNG position. They cover every 3.4 fixture listed in the build plan. Existing action-complete/parser-return tests additionally verify lexical records and source spans. Budget failures after a successful list mutation and just before the next READ restore the prior checkpoint. A quoted actor command reaching YES? proves that a prior speech tick remains committed while answering advances neither the sequence nor the clock. Startup, input and pending diagnostic checkpoints round-trip; malformed shapes, invalid roots and incompatible modes fail without affecting a live loop. Adapter ABI v15 retains the integrated boundary and quoted direction policy. Step 3.4 is complete; public lifecycle correlation and options/perception remain 3.7 and phase 4.


## Adjective-only bindings (3.9)

Operand also accepts `{object: "CANDY", adjective: "CANDIED"}` without a noun. This is a complete authored identity with source spelling, not typed inference. The adjective must occur on that source object. The adapter reproduces SNARFEM's adjective binding and GET-OBJECT's promotion only when the dictionary word also has an object role; it never updates P-ONEOBJ for a lone adjective. In particular, the original walkthrough's `candies` truncates to the same six-character dictionary encoding as CANDIED. The generated input uses the source spelling CANDIED. Source-only noun strings, explicit noun/adjective pairs and pseudo operands retain their existing behavior. ABI v15 makes this additional representation part of the build/save contract.
