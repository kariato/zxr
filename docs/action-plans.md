# Action plans (step 3.4a)

Player input uses predefined text choices for non-movement actions, mapped to structured option IDs. There is no microphone input, speech recognition or speech-to-text. References below to say/speech describe the game’s internal quoted-word semantics; those words come from the selected authored choice. Character audio is generated separately with local Python TTS on the Mac mini.

`prepareAction(game, world, action)` prepares owned, deterministic lexical data for a structured action. It is pure: it reads definitions and the current world, but never runs translated routines, activates pseudo features, consumes randomness or writes parser state. This is the first part of step 3.4; plans are consumed by the limited integration path described below; the full adapter remains incomplete.

Supported shapes are the design's `act`, `walk` and quoted `say`. PLAYER resolves through the current PLAYER global; other actor names identify source objects with ACTORBIT. Non-walk actions require the exact lexical table, one-based row and matching action name. The row must be the first matching object-count/preposition pattern in emitted syntax-table order. Operand counts must match the row. Unknown keys, invalid references, duplicate operands, two-sided multiplicity and different pseudo features sharing PSEUDO-OBJECT fail explicitly.

Plans include semantic build identity, an action ID encoding every supplied field in canonical JSON, the allocated syntax address/action, symbolic selections, lexical noun spans, canonical input records and quoted-speech continuation positions. Caller mutation cannot change a prepared plan. The ID is paired with the build hash; it does not supply the later epoch/revision protocol or authorize execution.

`ALL` remains an unresolved selection. Explicit lists retain their supplied order as input data; the runtime resolver must produce reference search order before filling match tables. Pseudo bindings identify the room, word and handler without modifying the shared object's name/action. Actor prefixes encode the comma input; the later adapter must perform the original COMMA-to-THEN rewrite and conditional TELL continuation. Speech records describe input before PARSER changes the count. These are not parser-return snapshots.

Noun spelling currently uses the entity's first source synonym, or a pseudo feature's word. It does not prove lexical uniqueness, visibility, reachability or a legal action in the current room. The later scope resolver must validate those conditions and may choose a distinguishing adjective. Options must never treat a plan as proof that a hidden or remote object is available.

`encodeReadText()` implements V3 input tokenization with the source's period/comma/quote separators. Dictionary lookup compares four encoded bytes, preserving the original six-z-character significance, punctuation encodings and unknown-word zero. Tokens retain original lengths and one-based byte offsets. `writeReadText()` validates capacities/overlap and writes into a fork: lowercase text and its terminator, word count and emitted records. Unused text/parse tails and both capacity bytes remain intact. One-word decision handling delegates to this same implementation.

Ten tests cover syntax addresses and matches against original parser checkpoints, quoted continuation globals, metadata/actor/pseudo validation, ALL and multiplicity representation, stable owned IDs, independent ifvms tokenization, buffer-tail retention and atomic capacity failures. The original tokenizer receives the source-built dictionary image; addresses therefore compare directly without relocating expected values.

The retained entry/check programs and ordinary nested scope now execute as described below. Actor speech, broader spoken command continuations, distinguishing spellings and complete exit acceptance remain pending. Step 3.4 remains open; the current coverage does not constitute a public action/session protocol.

## Retained source and limited execution (3.4b)

Bundles now carry source-derived parser `entry` and `checks` programs under adapter ABI `zxr-adapter-v7`; recompile older `.zxb` files. Entry keeps the original locals, ten-word table copy/reset loop, context reset and fresh/continuation arms. The unsupported reserve arm is omitted and rejected before entry. Checks retain the original short-circuit MANY-CHECK/TAKE-CHECK order and truth normalization, removing only SYNTAX-CHECK/SNARF-OBJECTS. Source sites remain under adapter policy. The ordinary routine map still excludes PARSER and all removed scanner IDs.

`Interpreter.executeAction()` accepts ordinary PLAYER syntax rows with zero, one or two operand slots, including ALL and one-sided explicit lists, plus directional walk. `executeSimpleAction()` remains a compatibility alias. It accepts quoted PLAYER ANSWER/SAY/INCANT through kind say; actor act/walk commands use the two-pass path below. Actor speech and speech verbs encoded as act remain rejected. Pseudo operands must name a source feature in the current room. Simultaneous multiplicity remains rejected. Global/local-global fallback executes the retained GLOBAL-CHECK helper. Nouns use the first source synonym; unresolved ambiguity fails atomically until distinguishing spellings are implemented. It executes the retained entry internally, fills READ records and parser fields, runs translated checks, and resumes MAIN-LOOP-1. PERFORM and CLOCKER remain translated code. Each fresh action starts its own step/output budget, while RNG state persists; any segment error restores the prior world, RNG, frames, budgets and output. Retained parser execution programs are explicit in frame checkpoints.

Scope executes translated DO-SL/SEARCH-LIST/THIS-IT? with the original room/inventory order, indirect clause first, lit-room PLAYER transparency toggle, and slot-bit retry on ambiguity. Open/transparent containers and searchable surfaces retain source traversal semantics. Search helpers populate the original direct/indirect match tables, preserving unused tails and retry writes. Parser fields include both match tables, preposition numbers/dictionary words and both noun spans. The scope controller is transaction-local and cannot be checkpointed or exposed at a host suspension. Adapter ABI v7 binds the widened execution policy, GLOBAL-CHECK helper, pseudo validation, PLAYER speech/HELLO continuation and actor act/walk passes into build/checkpoint identity.

This is an internal integration API, without option availability, correlated epoch/revision IDs or public ActionResolution wrapping. Its output includes the fresh parser prompt before the action, since the current low-level boundary is just before PARSER. Tests compare this with the original stream by accounting explicitly for that prompt placement. The later public input boundary must publish the retained prologue/READ before accepting an option.

A five-command TAKE/DROP/LOOK/south/north sequence matches original output, room/move counts, input-table words and selected parser globals using the original random tape. Checkpoints round-trip after every command. Separate tests cover retained source projection, startup READ memory, actor/quote context, table-tail preservation, MANY refusal, implicit taking, unsupported reserve state and complete error rollback. Full step 3.4 acceptance is still pending.

A fourteen-command original-story comparison covers lamp activation, travel to the gazebo, nested table contents, two-object PUT ON, EXAMINE, INVENTORY and WAIT. It compares exact output, room/moves, parser globals, and every object tree link and flag after every turn, with checkpoint restoration between turns. Scope fixtures cover closed opaque/transparent containers, dark inventory, ambiguous nouns, indirect scope failure and budget rollback. These are bounded acceptance cases, not full general-action conformance.

## ALL and explicit lists (3.4c)

Explicit lists resolve each canonical noun in lexical order and append matches, preserving table tails and retry writes. ALL supplies a zero noun filter and the syntax slot's scope bits; source traversal orders the resulting matches. Indirect clauses resolve first. P-AND, P-ONEOBJ and P-GETFLAGS retain conjunction/last-noun/cross-clause ALL behavior. The original MANY-CHECK/TAKE-CHECK and MAIN-LOOP-1 own refusals, implicit acquisition, per-object output/skips, M-END and one CLOCKER call per command. No native filter substitutes for the loop's TAKE ALL exceptions.

An empty local search invokes translated GLOBAL-CHECK, including room globals and the original global-object fallback. Explicit pseudo selections use this helper as described below. Missing/ambiguous canonical selections and an ALL search with no matches after global fallback still return an atomic integration error; parser orphaning and not-here substitution remain pending.

Original-story sequences cover ordered TAKE/DROP lists, TAKE/DROP ALL, empty-inventory DROP ALL's global fallback, indirect MANY refusal, mixed explicit success/failure, and TAKE ALL with a successful lamp acquisition and unicorn refusal. They compare output, all match-table words, input-table fields, selected parser globals, object flags/links, clock slots and RNG position. Execution checkpoints restore between turns. REF-001 below records the one bounded oracle-state exception.

The pinned ifvms 1.1.6 REMOVE implementation leaves a stale sibling word on detached objects. ZXR clears it and preserves a valid tree. The comparison normalizes only detached sibling words, checks that the engine word is zero, and requires each scenario to declare the exact affected object names (UNICORN in the mixed TAKE ALL case). A separate three-object regression demonstrates the pinned behavior. See [reference evidence](reference-audit.md#reference-interpreter-remove-quirk-ref-001). No binary, vendored source or existing transcript is changed.

## Explicit room pseudo features (3.4d)

An operand `{pseudo:{room,word}}` now executes through the same scope/search path as ordinary nouns. The retained GLOBAL-CHECK matches the current room's PSEUDO property, changes the shared PSEUDO-OBJECT ACTION property and copies the dictionary word's encoded name bytes into its short-name storage. Native code does not duplicate these writes. Planning remains pure. Both direct and indirect selection, explicit lists and the same feature in both slots use the existing checks/turn loop. Different pseudo features sharing the proxy remain rejected during planning.

Execution checks the declared room after the retained parser entry establishes HERE, then verifies that global fallback selected the proxy and bound the planned handler/name. A stale or modified handler, an ambiguous/colliding spelling or a feature from another room cannot silently select a different feature. Integration errors, later operand failures and output/step limits roll back the proxy's property/name writes with the rest of the command. Checkpoints include the binding in ordinary world memory.

The Tea Room oracle sequence covers EXAMINE HOLE, LOOK IN HOLE, PUT LAMP IN HOLE, TAKE HOLE, PUT HOLE IN HOLE, EXAMINE HOLE AND LAMP and repeated examination. The Great Cavern sequence switches STALAGMITE/STALACTITE, while a prepared-world regression switches the shared proxy from Tea Room to Great Cavern and restores its checkpoint. Every oracle comparison checks the handler's relocated routine identity and all four name bytes, alongside the existing parser tables, output, objects, clock slots and RNG positions.

These targeted oracle runs use explicitly marked prepared contexts, to isolate the handlers from the journey and puzzle prerequisites. They were introduced before speech support; separate riddle tests now exercise quoted answers on a natural journey. Both engines run GO first, then move the player and supplied inventory to the same naturally lit room without consuming turns or RNG. The original interpreter continues the actual parser/handlers/clock from its first READ. This proves contextual command behavior; it does not claim an end-to-end journey to the Tea Room. Default recordings are unchanged, prepared results carry `preparedContext`, and the startup audit rejects them as startup evidence.

## Quoted PLAYER speech (3.4e)

`kind:say` now executes canonical quoted ANSWER, SAY and INCANT data. The adapter writes the original quote flag, P-CONT word index, P-LEN and remaining P-LEXV count at the opening quote, preserving all token addresses, byte lengths/offsets and unused records. Unknown dictionary words remain zero inside the data. Translated room/actor/object handlers and verb routines consume the words, cancel continuation and delegate SAY to INCANT when SPELL-USED or WAND-ON requires it. The native adapter does not interpret riddle answers or spell effects.

If translated SAY leaves a single HELLO pending, the adapter executes the retained continuation entry without a new READ, keeps the original token's byte offset in P-VTBL, processes the terminal quote state and dispatches the original HELLO syntax/checks/verb. The original two MAIN-LOOP-1/CLOCKER iterations are preserved: in the barrow SAY "HELLO" consumes two moves. Step/output limits and rollback span both passes; RNG state is not reset. If a handler consumes HELLO (for example the riddle's HELLO WELL answer, an actor-present refusal or wand delegation), its cancellation prevents this continuation.

The temporary speech/HELLO plans are transaction-local and cannot be published or checkpointed mid-adaptation. Actor speech, arbitrary command text left pending by SAY (such as HELLO LAMP), and host suspension while this speech controller is active remain unsupported; they fail atomically. This is a bounded structured-speech path, not a restored free-text parser. Public decision/lifecycle correlation and actor speech remain later work.

Original-story comparisons cover unknown quoted data, ordinary speech/incantation, HELLO and its two passes, actor-present cancellation, wand delegation, and wrong/correct riddle answers with WELL in the first or second word. Four riddle variants reach the room through ordinary startup, lamp use and movement, including the carousel's original random exits, then walk through the opened door. Tests compare output, score, moves, selected parser/quote globals, all emitted lexical records/counts, verb spans, match tables, object state, clock slots and RNG position, with checkpoint restoration between commands. Unsupported continuation and output/step-limit failures restore the complete pre-utterance state.

## Actor act/walk commands (3.4f)

A non-player actor now uses the original two-pass flow. The first retained entry reads the complete canonical `robot, ...` input. The adapter rewrites the comma's dictionary record to THEN while retaining its original byte length/offset, fills the implicit TELL syntax and actor noun span, keeps P-VERBN zero and preserves the previous P-VTBL, and sets the original quote/remaining-count/continuation fields. Ordinary scope helpers validate the actor; translated checks, MAIN-LOOP-1, object handlers and V-TELL run. Only translated V-TELL assigns WINNER and HERE for an accepted command.

At the next parser call, an accepted TELL continues through the retained P-CONT entry without another READ. The adapter supplies the planned act/walk syntax with the original prefixed noun pointers and verb offset. Source quote state preserves the actor during entry, then the completed command clears the quote flag as the original scanner does. The same scope helpers, checks, PERFORM and CLOCKER execute. TELL is exempt from CLOCKER; the requested robot command normally consumes one move. A handler such as the unicorn's HELLO? may cancel TELL and the continuation, in which case the requested action does not execute and no TELL clock tick is added.

The current low-level API publishes just before the next PARSER call. Its world therefore matches the original actor action-complete checkpoint, which may still have WINNER/HERE referring to the actor. The next fresh retained entry restores PLAYER, META-LOC/HERE and LIT exactly as source code specifies; no native reset is inserted. The cage rescue handler itself switches WINNER back to the adventurer and performs GOTO. A future public boundary still needs to run the fresh prologue/READ before accepting options.

Prepared-context oracle sequences cover robot movement, GIVE and robot TAKE/DROP, explicit inventory lists, refusal of LOOK, following the robot through rooms, the player's sphere trap and `robot, raise cage` rescue, then player LOOK. A natural-route unicorn command proves handler cancellation before the second pass. Comparisons include both P-ITBL and the retained first pass in P-OTBL, all lexical records (including THEN), match-table tails, actor globals, output, object state, clock slots and RNG position. Checkpoints restore after every command. Missing operands, remote/invisible actors and execution budgets roll back both passes and their parser/global/RNG mutations.

Actor speech, unexpected extra continuations and host suspension while the actor controller is active remain unsupported integration cases and fail atomically. The actor prefix currently requires one canonical noun token followed by comma. Complete exit acceptance and the public session protocol remain open.

## Implicit taking, vehicle context and dispatch acceptance (3.4g)

Complete-turn comparisons now verify that original TAKE-CHECK implicitly acquires a ground-level lamp for TURN OFF and WAVE, while each requested action consumes one move. The adapter does not acquire objects itself.

A 28-command journey obtains a lamp and teapot, fills the teapot at the ford, solves the riddle and reaches the well through ordinary movement. It puts the lamp in the bucket, tests the container's refusal to let the player take it from outside, boards, takes it from inside, looks, pours water into the bucket, rises to the well top through the bucket's M-END handler, and disembarks. Exact original output, parser buffers and syntax-row bytes, all object links/flags, moves, clock slots and RNG position match, with checkpoint restoration after every action. This exercises HERE retention when the player's immediate container is a vehicle and the bucket's nested movement/LOOK calls. The fixture selects the explicit POUR IN row; POUR FROM shares the DROP action but has different syntax bytes.

A separate synthetic dispatch fixture extracts the active macro-expanded PERFORM routine directly from the unchanged original source. Synthetic objects supply handlers at all eight layers: not-here, actor, room M-BEG, preaction, indirect object, direct object's container, direct object and default verb. Trace assertions verify the complete order, stopping and return-value propagation at each layer, and restoration of PRSA/PRSO/PRSI. A nested PERFORM(WALK) verifies restoration inside the outer indirect handler and WALK's suppression of direct/container dispatch. This is a source execution test with synthetic handlers, not an original-story oracle recording. It adds no runtime tracing callbacks or headless host dependencies.
