# Phase 2 progress: compatibility, world, vocabulary and routine logic

Steps **2.0–2.10 are complete**. The compatibility candidate was presented for review, then Mark instructed “next” on 2026-10-21; that authorizes continuing with its contracts. Steps 2.0–2.2 were committed as `20de48a` and 2.3–2.7 as `c3d325b`; steps 2.8–2.10 and the first phase 3 work are currently uncommitted.

The accepted [compatibility specification](compat-semantics.md) gives concrete contracts for the six draft obligations, backed by `reference/semantics-inventory.json` and `reference/semantics-probes.json`.

| Obligation | Evidence and decision |
|---|---|
| Spoken/actor input | Exact V3 byte/word units, quoted token positions and continuation flags from twelve binary scenarios; preserve actor context until the next fresh input. |
| Parser output | All ten P-ITBL fields, eight syntax bytes, counted match tables and explicit global ownership. ACT?, V?, W? and lexical syntax identity are distinct. MANY can occupy the indirect slot. |
| Primitives | All 439 active routines, including argument initializers, contain 70 executable operation names. An independently declared contract rejects added/removed names. Debug stream operations fail explicitly. |
| Header | Ten literal-base-zero AST sites in five routines: release/serial, transcript flag and fixed-font flag. General computed accesses still need symbol/segment validation. |
| Conformance exclusions | Every one of 168 globals classified; 21 named scratch exclusions with reasons, sixteen parser buffers and three protocol references checked separately. Mutable gameplay table contents remain included. |
| Numbers | Retain original object/global/property/flag/action numbering and dictionary order. Byte representations make generic handles unsafe; dictionary values are relocated addresses, string values are handles. |

The evidence changes three important assumptions in the draft:

- PARSER does not preassign PRSO/PRSI. The first TAKE LAMP returns with PRSO=0 but LAMP in P-PRSO. ITAKE-CHECK can subsequently change PRSO during implicit taking. Directional parsing retains the previous syntax pointer.
- READ overwrites the records it emits, leaving unused lexical bytes intact. SOUTH after TAKE ALL retains ALL beyond the live count. Clearing the entire buffer would change compatibility state.
- Quoted speech can continue after the first action. SAY HELLO outside a consuming handler performs SAY then HELLO, costing two moves. Robot commands perform a zero-move TELL pass before their action; a refused/cancelled continuation must not force a second pass.

The wand scenario consumes FLOAT through P-CONT. The riddle scenarios distinguish ANSWER WELL (REPLY) from ANSWER "WELL" (ANSWER). Other scenarios cover implicit taking, the pseudo-object's truncated encoded short name, nested YES? input, and transcript-header writes.

The proposed contract also resolves the runtime-facing gaps in review round three: primitive saves include complete interpreter continuations; host completions have operation identity; replay embeds restore payloads; the semantic build hash includes initial world/layout and ABI; non-clock mutable tables are compared; and rollback restores all state to the latest exposed boundary. These are specification decisions with future runtime acceptance checks, not working engine features.

## Step 2.1: symbol table and name resolution

`src/zil/symbols.ts` is the headless implementation. It receives a loaded/expanded program and an injected numbering layout; it reads no files and imports no reference interpreter. `analyzeSymbols()` returns declarations, every resolved use with a full source span and access mode, routine/local scopes, and accumulated diagnostics. Unknown names, invalid writes/calls, cross-kind duplicates, duplicate locals/defaults, malformed bindings, unknown metadata names, bad reference numbering and constant cycles fail explicitly.

`tools/zil/symbols.ts` supplies the reference-assisted layout and a reproducible `reference/symbol-table.json`. It contains 439 routines, 86 rooms, 165 objects, 168 globals, 30 named properties, 32 attributes, 148 actions, 135 lexical verbs, 18 prepositions, 141 adjective codes and 689 dictionary entries. All **11,901 uses resolve with zero diagnostics**, including argument defaults, object metadata, exits, syntax declarations and table initializers. A reference record does not create a missing source declaration: deleting a global or routine is still an error.

Number domains are explicit:

- Objects use the original `.OBJECT` order, starting at 1; globals use 16 plus `.GVAR` index. PRSA actions (V?) and lexical verb-table codes (ACT?) are separate symbols. VERBOSE's action is legitimately zero; attribute zero is also valid.
- Routines use stable IDs starting at 1 in audited assembly order; zero remains the false routine. These are ZXR IDs rather than bytecode pointers.
- Dictionary entries carry a stable one-based index and an oracle address. Their runtime numeric address stays unallocated (`number: null`) until the memory-layout step. An independent V3 encoder compares all 689 `.ZWORD` encodings to the binary at their inferred addresses. Words cannot accidentally become dictionary ordinals at runtime.
- Locals have deterministic slots and required/optional/AUX/block kinds. Defaults resolve earlier bindings; a nested block can shadow an outer local without leaking it. Bare variable names and dot/comma loads have distinct reference modes. Constant arithmetic wraps after each operation, supports forward aliases, and rejects cycles, zero divisors and mismatches with audited numeric constants.

The manifest stores the definitions/scopes and a hash of the complete resolved-use stream rather than duplicating all spans in a large artifact. The full use stream is available from the headless API. It is not compiled logic, an allocated memory image or a `.zxb` bundle.

### Findings recorded while resolving names

**SRC-006:** DREARY-ROOM-FCN ends with `(T <PCHECK> <RFALSE>)` outside its COND. Generic executable-list semantics would conceal a source/compiler interpretation issue. The binary/assembly target clearly calls PCHECK and returns false after the look branch. `tools/zil/reference-program.ts` normalizes exactly that routine's trailing list to an unconditional PROG, preserving source positions and normalization metadata. A complete expanded-routine hash and assembly anchor guard the rule. Tests prove changed source is rejected and arbitrary executable lists remain unsupported. This is an explicit compatibility rule, not a modification of the vendored source or a claim about the unavailable original compiler.

**SRC-007:** ITABLE NONE 180 reserves 180 words (360 bytes), while C-TABLELEN=180 counts the byte range the clock scans. Match tables reserve 50 words (100 bytes); P-OCLAUSE reserves 100 words. The phase 2.0 candidate incorrectly described NONE 180 as a 180-byte allocation. The specification is corrected before any memory image exists. Table emission and byte-for-byte checks remain step 2.7.

`zxr check reference/zork2` now includes symbol checks automatically. `zxr check --symbols path/to/zork2-copy` applies the same reference numbering to a source copy and reports absolute file/line/column plus a caret. Other entries retain reader/macro checks; self-assigned numbering remains deferred. `compile` and `play` still exit nonzero with explicit unimplemented messages. CI runs the symbol audit and the packaged CLI.

## Step 2.2: room/object JSON

## Step 2.4: vocabulary and syntax tables

Syntax declarations are prepended to their table, as the original compiler did. The generated order matches every assembly and binary row, including ANSWER's REPLY row before its zero-object ANSWER row. Syntax IDs are one-based within a lexical table, and a row starts at byte offset `1 + (id - 1) * 8` after the count byte. The JSON preserves this order rather than sorting by action or source position; source spans still point at the original declarations, including escaped debug verb names. Lexical verb code (ACT?), action number (V?), dictionary index and routine ID remain separate domains. VERBOSE's action number zero is valid.

Each row retains zero, one or two object slots, prepositions, FIND attribute hints, symbolic operand rules and exact eight-byte encoding. HELD=128, CARRIED=64, IN-ROOM=32, ON-GROUND=16, TAKE=8, MANY=4 and HAVE=2 match the original constants. FIND is retained independently from these bits, including an attribute numbered zero; it does not filter candidates. HAVE/TAKE remain possession rules for later commit checks, scope hints remain hints, and MANY can appear on the indirect slot (GIVE). This stage emits data; it does not run handlers or resolve objects.

Word roles are derived from syntax, object/room synonyms and adjectives, pseudo words, explicit word references, BUZZ and DIRECTIONS. LIGHT remains both noun and verb; IN remains preposition and direction; N inherits NORTH's adjective and direction roles; THROUGH uses WITH's preposition code. ## Step 2.5: core routine translation

`src/zil/logic.ts` lowers all **439 normalized active routines** to typed, JSON-safe, partial core IR. It implements lowering for the 34 inventoried core operations: arithmetic/bit operations and comparisons; SET, SETG, VALUE and variable update/compare; ordered COND/AND/OR; PROG/REPEAT bindings; RETURN, AGAIN, RTRUE/RFALSE, PUSH/RSTACK; and direct calls/APPLY. There is no runtime evaluator yet. Operator nodes preserve the operations for the phase 3 interpreter to implement with the compatibility contract's 16-bit rules; this step does not claim arithmetic execution conformance.

Commands use an `evaluate` wrapper around an expression, keeping the command/expression types separate while retaining values from nested mutations and control forms. A routine or PROG falls through with its last expression (or true for an empty body); an unselected COND returns false, a bodyless selected clause returns its test, and AND/OR retain deciding values. Their ordered arrays remain explicit, so no compiler folding duplicates or reorders a side-effecting operand. Direct calls retain routine IDs; APPLY retains its routine expression separately from its ordered arguments, including a zero routine and explicitly supplied zero arguments.

Routine bindings carry required/optional/AUX kind and initializer, in source order. Required bindings have no initializer; omitted optional/AUX initializers are explicit zero. A supplied optional zero is distinguished from omission by the call's argument count. Initializers resolve earlier bindings before introducing their own shadowing name. PROG/REPEAT have separate binding arrays and stable routine-local block IDs. Lexical slots follow the resolved symbol scopes; bare names produce variable numbers, dot references load locals, comma references select global symbols, and SET/SETG preserve their distinct targets. Variable update/compare retains a named target and the bound expression, which must be evaluated once under the general argument-evaluation rule before applying the primitive. This bootstrap rejects more than fifteen local slots rather than colliding with global numbers; the selected game needs at most twelve.

RETURN records its nearest block target, or the routine target outside a block. RTRUE/RFALSE and RSTACK always return from the routine. AGAIN explicitly records its nearest block or implicit routine-body target, retaining the activation rather than reinitializing it. **SRC-009** clarifies the draft's missing routine-level case: GO's final AGAIN compiles in the supplied assembly as JUMP ?FCN, back to its first body instruction. The source and assembly remain unchanged. PUSH/RSTACK keep frame-stack operations explicit, including macro-expanded RFATAL. DECL type metadata is removed from command bodies; macro call/definition origins and source spans remain on lowered nodes. Stable source-map IDs remain step 2.9.

The artifact is tagged `stage: "core"`. **32 routines** have no deferred construct in their own body/defaults; that flag does not certify their callees, initialized world memory or executability. **5,109 sites** remain explicit `untranslated` nodes/report entries for object/output/random/host/string operations (2.6), memory operations and dictionary addresses (2.7). Nested supported expressions inside these nodes still lower. No numeric string or dictionary handle is fabricated. `assertFullyLoweredLogic()` walks the actual trees and refuses a partial program even if someone removes its report. Invalid arities, call signatures, targets or unrecognized constructs fail with source-located ZIL009 diagnostics.

`tools/zil/logic.ts` independently compares operation counts in each normalized source routine with the IR traversal, verifies all fixed routine IDs and checks that every deferred IR node appears in the report. `reference/logic-core.json` records source and complete IR hashes, per-routine counts/hashes and all deferred locations; it avoids checking in the much larger full IR before later operations and memory are implemented. The headless API returns the complete trees. `logic:record` generates the report only after the structural audit; `logic:check` verifies it without writing and runs in CI. Reference-assisted `zxr check` now performs this lowering pass, reports the remaining sites and diagnoses malformed core code in source copies. `compile` and `play` still refuse as unimplemented.

Eleven new tests cover four hand-authored trees (NULL-F, MAIN-LOOP, SCORE-UPD and DO-WALK), ordered defaults/AUX, lexical shadows, variable-number/load distinctions, nested block/routine return and restart targets, RFATAL provenance and frame stack operations, all arithmetic/comparison forms, short-circuit/COND value structure, fallthrough, direct/recursive/indirect calls, declaration stripping, deferred constructs, source spans, invalid arities and report/IR mutations. The CLI test verifies absolute file/line/caret output for a malformed SETG. Operation conservation plus these structural checks is not a proof of semantic equivalence: numeric behavior, stepping, budgets, suspension and golden transcript conformance remain phase 3.

## Step 2.8 — parser library split

`src/zil/parser.ts` classifies all **42 gparser routines**: **15 kept**, **26 replaced-middle**, and **PARSER as the adapter entry**. GLOBAL-CHECK was added during phase 3.4 to retain original global fallback for ALL and ordinary noun lookup. Required adapter helpers and direct calls from every non-parser routine seed retention; the transitive parser-helper closure is retained. The 15 are WORD-PRINT, BUFFER-PRINT, GLOBAL-CHECK, DO-SL, SEARCH-LIST, OBJ-FOUND, TAKE-CHECK, ITAKE-CHECK, MANY-CHECK, ZMEMQ, ZMEMQB, LIT?, THIS-IT?, ACCESSIBLE? and META-LOC. The runtime view contains **412 routines**, preserving every original ZXR ID and excluding the adapter's original body and the replaced middle. The complete 439-routine linked IR remains available for audits.

Each parser row records source spans, retention reasons, direct calls, full call closure and direct/transitive may-effects. The analysis visits defaults, AUX and nested block initializers and every branch. A fixed point carries pointer origins through local assignments, REST/BACK, arithmetic, recursive calls and argument substitution. This captures OBJ-FOUND's writes through its second formal, SEARCH-LIST's forwarded table and DO-SL's P-TABLE. LIT?'s explicit writes are HERE, P-GWIMBIT, P-SLOCBITS and P-TABLE; its memory effects include the buffers named by P-MERGE and P-TABLE. These are writes through pointer values, not assignment to the P-MERGE global slot.

Memory-base labels are symbolic runtime global values, formal argument slots, allocations, properties or `unknown`. They may alias. Unknown includes every address, including globals, and is never discarded as pure. Explicit global writes, object mutations, output, RNG and host effects are separate fields. This is conservative flow-insensitive analysis, not a complete points-to, execution or purity proof. The dispatch boundary prohibits **all translated routines during options queries**. Kept helpers run only in action/adapter transactions.

All **16 APPLY sites** have classified domains: routine-valued properties ACTION/CONTFCN/DESCFCN, action/preaction dispatch tables, clock records and functional exits. Their target sets deliberately over-approximate all **312 named first-class routine values** in the linked IR and initial memory. No parser routine appears in that set. New unclassified APPLY domains, invalid routine references, first-class references to removed/adapter entries, or retained calls back into removed code fail with ZIL012. MAIN-LOOP-1's direct PARSER call remains the approved adapter boundary.
