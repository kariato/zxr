## Loader

`LoadedGame.load()`/`loadGame()` accept bundle text or UTF-8 bytes. They validate schema, ABI/version contracts, semantic/presentation/content hashes and cross-file references before exposing data. Definitions are owned and frozen recursively. Routine lookup excludes replaced parser bodies; `createInitialMemory()` returns an independent copy. `createRandom()` creates an independent RNG from the bundle's initialization seed or an explicitly supplied oracle tape.

## World state

`WorldState.create(game)` builds the pre-GO image. Globals, ordered parent/child/sibling links, flags, short-name bytes and property data share the same authoritative memory. MOVE inserts first and unlinks the old position; REMOVE detaches. Cycle and invalid-object checks precede structural writes. All 32 attribute bits work, including the high signed bit.

GET/GETB/PUT/PUTB share big-endian storage, including unaligned word accesses that fit one allocation. Static segments, padding and protected header bytes cannot be written. Only header word 8 is writable. Pointer arithmetic and accesses reject overflow and crossing an allocation's bounds. Bounds are defined by the complete operation and numeric base address, including one-past endpoints; at an adjacent shared boundary the same address can belong to the preceding pointer range or following allocation. Reads/writes must fit wholly in a real allocation. There is no hidden pointer provenance in a 16-bit word. SRC-012 records this clarification of the earlier “one-past cannot be dereferenced” wording.

The property API supports defaults, raw addresses, lengths, descending NEXTP order and existing one/two-byte PUTP. PSEUDO-OBJECT retains its required ACTION-minus-five short-name storage. `validate()` checks protected memory, ordered-tree membership/cycles, property pointer/header/length invariants, explicit reference domains and the core HERE/PLAYER/WINNER/pronoun object globals. This is not yet full dynamic operand-domain inference or a complete engine-save validator.

Memory forks share 256-byte pages until a write. Both parent and child detach a shared page before mutation, including nested forks. `snapshot()`/`WorldState.restore()` own their bytes, check the semantic build hash and validate before exposing restored state. `worldHash()` hashes this world-only snapshot. These are not complete saves: execution frames, RNG, decisions and knowledge gates must be included by the later interpreter/checkpoint layer.

Ten tests cover initial source-built bytes and all object-parent links, ordered mutations, invalid cycles, every attribute bit, byte/word aliasing, globals, header/static/allocation guards, pointer boundaries, property defaults/layouts, independent forks and corrupted snapshots/references. The original-memory relocation audit remains independent evidence for initial values. WorldState alone remains pre-GO. The evaluator now runs GO and compares its output, all 251 object link/flag records and every global without an initial address/string/routine relocation against the original's first READ checkpoint. The input prompt belongs to the not-yet-run adapter and is excluded explicitly. Initial relocation values are independently covered by the phase 2 memory audit. Short names use the independent original decoder. A deliberate clock-table corruption fails the audit. This completes the step 3.1 startup check; general per-command comparison remains later work.

## Interpreter primitives

`numeric.ts` implements signed-word arithmetic, wrapping, truncating division, dividend-signed remainder, bitwise tests, equality and signed comparisons. Variable update/compare returns both the new word and predicate result; the continuation evaluator controls operand evaluation and assignment order. Short-circuit forms are deliberately not eager ALU operations.

`GameRandom` owns deterministic xorshift32 state. Zero reseeds to the configured seed; negative signed bounds reseed with their magnitude; positive bounds return 1..n using rejection sampling over xorshift32’s nonzero-word domain. `assertReplayComplete()` rejects an unused tape tail at conformance completion. Snapshots include seed/state, draw position, replay cursor and tape identity. Replay validates every range, including reseeds, and errors on mismatch/exhaustion without advancing state. Tests replay the existing area-barrow oracle tape, whose original RNG algorithm remains a separate reference setting. The engine's ordinary algorithm is not claimed to equal the original interpreter's MT19937.

`decodeZText` decodes compiler-emitted V3 short names and dictionary words with explicit word bounds. It handles alphabet shifts, punctuation, newlines and ASCII ZSCII escapes, and rejects unsupported abbreviations/malformed data. All 251 object short names match source metadata; all 689 dictionary encodings match the independent original-story decoder. General abbreviation-table execution is unnecessary for the emitted data image and remains unsupported.

Eight ALU/RNG tests and four text tests cover fixed vectors, signed boundaries, arithmetic errors, replay mismatch/restore/aliasing, original dictionary decoding and invalid text bounds/escapes. The headless boundary check continues to prohibit host I/O, clocks and ambient randomness.

## Continuation evaluator

`Interpreter` runs mapped IR with explicit routine frames, local words, per-frame operand stacks and expression/block activation cursors. Arguments evaluate left to right once; supplied optional zero skips the default. Defaults/AUX and block bindings initialize in source order. AND/OR/COND short-circuit and preserve deciding values. RETURN selects its compiled block/routine target; AGAIN retains that activation’s bindings; routine returns and RSTACK unwind nested blocks. APPLY zero returns zero after evaluating its arguments, and nonzero targets go through guarded runtime routine lookup.

The evaluator implements numeric, memory, object/property, output, RNG and VERIFY operations. Dictionary output reads encoded dictionary addresses; object output reads mutable short-name bytes. Direct PARSER calls suspend only from MAIN-LOOP-1; indirect adapter calls and removed routine IDs are rejected. Unsupported streams fail explicitly. There is no host I/O in this layer.

READ/SAVE/RESTORE/RESTART/QUIT retain an explicit suspended expression and its enclosing operand/call continuations. The low-level `resume()` accepts SAVE success/failure and RESTORE/RESTART failure. It rejects raw READ/parser results; the decision-only `answer()` adapter supplies READ buffers, and rejects successful session replacement operations directly. GameSession owns replacement and the public host request IDs, epochs and revisions.

Each run/resume segment forks world memory and clones frames, stacks, cursors and RNG state. The structural world validator runs before publishing each boundary. An error discards unreturned output/random events and restores that complete execution state. Prior returned text and host suspensions remain committed. Step, call-depth, expression-stack, operand-stack and output limits bound execution; counters persist across suspensions. `world()` returns an independent fork. `inspect()` returns owned JSON-safe diagnostics, including the continuation and RNG cursor; it is **not** a validated external checkpoint/import format.

Twenty evaluator tests cover hand-written three-room execution, argument ordering/defaults, short circuits, recursive frames, block/routine AGAIN, nonlocal returns and operand stacks, dynamic calls, object/flag/memory operations, signed pointer offsets, output domains, host suspension/resumption, diagnostic ownership, checkpoint round-trips/rejection, budgets, rollback and original-story startup text/object/global comparison. The comparison deliberately stops before parser adaptation and does not claim full per-command conformance.

## Execution checkpoints

`checkpoint()` returns owned memory, frames/locals/operand stacks, execution-program identity, expression and block cursors, primitive wait, return value, RNG state/tape identity, configured limits and consumed budgets. `stateHash()` hashes that complete low-level state. `Interpreter.restore()` first checks a strict shape/resource schema, canonical JSON constraints, semantic build identity and frame relationships against the loaded IR. It validates expression cursors/operand counts, block ownership, activation indices, pending callee arguments and suspension identity, then independently validates world memory and RNG identity/state. It constructs a new instance, so rejected input cannot alter an existing execution.

Tests serialize/deserialize nested SAVE inside a call/block, restore an original-story parser suspension, resume the same future result, preserve RNG replay position and budgets, reject corrupted shapes/references/frames/static bytes/tape identities and verify failure leaves the original hash unchanged. This `zxr-interpreter-checkpoint-v1` format is an execution-core checkpoint, not the public boundary/primitive-save envelope. The public envelope and SAVE-success restoration rules are implemented above this core in GameSession (3.7 below).

## One-word READ decisions

`writeReadWord()` implements the V3 overwrite rule in an independent memory fork: preserve both capacity bytes; write lowercase text and a zero terminator; write count one, the relocated dictionary word, token length and text offset one; retain all unused text/parse tail bytes. Unknown words keep dictionary zero. It bounds-checks the declared capacities and rejects overlapping buffers. Failed writes cannot partially alter the supplied world.

`Interpreter.answer()` accepts YES/NO only in translated YES?, and RESTART/RESTORE/QUIT only in translated FINISH. It writes the original READ operands and resumes that expression transactionally. These are internal choices without public decision IDs; epoch/revision correlation remains the lifecycle layer’s responsibility. The translated routines select their own branches and host operations.

Seven tests cover exact buffer writes and unused tails, unknown words, malformed/capacity/protection/overlap errors, serialized YES? continuations, V-QUIT’s exact original prompt and NO response without a move, affirmative buffers against the original story, all FINISH host branches and repeated prompts after failure, and rollback/source diagnostics on a failed decision write.

## Completed turn loop (3.4)

`TurnLoop` starts translated GO and runs MAIN-LOOP-1 through the retained PARSER prologue to its actual fresh READ. Startup includes the original prompt. `execute(action)` resolves a complete structured choice and continues through translated checks, PERFORM, M-END and CLOCKER until the next fresh READ, decision READ or host primitive. No handwritten clock, room handler or verb replaces the source. The returned `TurnResolution` contains accepted action sequence, status, exact ordered text, move count, source-derived clock ticks for this segment, random events and the current execution boundary. This is the execution portion of the later public ActionResolution; it supplies no invented presentation events or unfiltered player observation.

The next fresh prologue runs before a result is published: actor WINNER/HERE/LIT reset at the source's original point, vehicle context stays intact, match counts clear and P-ITBL copies to P-OTBL. Prompts belong to the segment that produced them, so successive results match the original transcript without moving prompts between actions. The legacy low-level Interpreter still defaults to its pre-PARSER diagnostic boundary for parser-return/action-complete comparisons. `inputBoundary: 'read'` selects the integrated path and participates in validated checkpoints. Raw READ text submission is confined to standalone diagnostic fragments; integrated commands require structured actions.

The adapter supports ordinary zero/one/two-object actions, source noun/adjective spellings, global and nested scope, ALL and one-sided lists, pseudo features, actor TELL/command passes, puzzle speech and bound quoted actions. Missing explicit operands and exhausted ALL searches run the source GET-OBJECT missing-match arm; translated checks and dispatch decide refusals and mixed-list results. A surviving bare quoted direction takes the original direction fast path, preserving prior syntax/verb and remaining quote/count state. Ambiguity, identity mismatches, incompatible pseudo bindings, simultaneous multiplicity, orphan/reserve input and unbound multi-word command text are explicit action-language rejections/errors, not unfinished source-loop branches. They remain listed in the action contract and rules ledger; there is no free-text or speech-recognition input.

One accepted fresh choice gets one action sequence even across several source passes or a suspended YES?/FINISH or host primitive. Source decisions and primitive results resume the same command and budget. Ordinary actions are refused while one is pending. Late failures restore the last exposed boundary, including memory, RNG, frames, output, budgets and sequence; an already returned prompt or earlier segment remains committed. Diagnostic turn checkpoints round-trip startup, input, decisions and host boundaries, validate the startup continuation and never serve as public save envelopes.

## Completed clock acceptance (3.5)

The engine already executes the original QUEUE, INT and CLOCKER from gclock.zil; step 3.5 verifies their behavior without adding a native scheduler or changing vendored game code. The compiled runtime has exactly the original two direct CLOCKER call sites, in MAIN-LOOP-1 and V-WAIT. Ordinary execution still advances time only through these routines. No timer, host clock or query drives them.

Sixteen clock tests extract the unchanged scheduler and macro-expanded V-WAIT for focused execution, then run the full compiled game against the original binary. Focused cases prove backward allocation of six-byte slots, reuse without implicitly enabling or resetting demon bounds, disabled/zero/positive/negative ticks, signed wrapping, the P-WON demon window, and CLOCK-WAIT's one-call suppression. Negative timers decrement and fire each eligible scan; they are not replaced by a native “repeat forever” flag. A true callback sets CLOCKER's result while the scan continues; V-WAIT consumes that result to stop early. Callback changes to later slots take effect during the current scan, while new slots prepended before its current cursor wait until the next scan. Requeueing a callback changes the next due time. Callback errors roll back queue writes, random draws, output and moves.

## Completed seeded determinism (3.6)

TurnLoop and Interpreter now accept an optional unsigned 32-bit `seed`. Omitting it keeps the bundle's default. A configured seed belongs to one run; it never changes the frozen LoadedGame, its semantic build hash or another run. LoadedGame.createRandom retains its existing optional replay argument and also accepts an explicit seed. Interpreter.restore and TurnLoop.restore construct their RNG from the checkpoint's recorded initialSeed, so custom seeds, including zero and 0xffffffff, survive both pristine startup and later continuations without an out-of-band seed argument. The existing checkpoint shape already contains that seed, state, request position and replay identity; no bundle/schema migration or RNG algorithm change is needed.

```ts
const loop = new TurnLoop(game, { seed: 37 });
const opening = loop.start();
const checkpoint = JSON.parse(JSON.stringify(loop.checkpoint()));
const continued = TurnLoop.restore(game, checkpoint); // recorded seed is retained
```

GameRandom remains xorshift32-v1. It uses nonzero 32-bit state and rejection sampling over its 2^32 - 1 word domain for inclusive 1..n results. Seed zero maps to the fixed nonzero state 0x6d2b79f5. A negative signed-word RANDOM reseeds with its magnitude; RANDOM 0 resets to the run's configured initial seed, independently of intervening negative reseeds. Neither operation uses host entropy. The diagnostic position counts successful ZIL RANDOM requests, including reseeds, rather than internal words rejected during sampling. It is monotonic until a transaction rollback; a restored counter at Number.MAX_SAFE_INTEGER now reports exhaustion before mutating state or emitting an event, keeping future checkpoints/hash inputs valid.

Twenty-one new determinism tests run normal gameplay without an oracle tape. Five seeds (0, 1, 2, 19 and 0xffffffff) execute the same structured choices in independent twins, comparing each returned packet and complete state hash. Unrelated RNG calls interleave between inputs, caller option objects change after construction, input property order differs, and one twin is reconstructed from JSON after every boundary. The sequence includes clock-driven random game behavior, two-pass speech, movement, inventory/score, a SAVE success and a declined quit. Diagnostic request counts equal the returned event count and remain independent of replay cursors. Different selected seeds produce different actual game draw streams; equality is not established merely by hashing the initial seed.

An independent arbitrary-precision model verifies 5,000 normal draws across five seeds and seven ranges, including 1, 100, 300 and 32767. A constructed inverse-xorshift state forces a high-remainder rejection; the result and final state agree with the independent model while position advances exactly once. The actual original PROB macro and ZPROB body execute in a small fixture: probability tests keep the source's strict greater-than threshold, and LUCKY selects RANDOM 100 versus RANDOM 300. Additional cases cover signed-minimum reseeding, return to the configured seed after RANDOM 0, invalid seeds, selected seed plus replay checkpoint identity, owned query results, rejected inputs, and execution/hashing with ambient Math.random and Date.now disabled.

Late step/output failures after random game work restore all request/state words, events and the complete prior turn checkpoint. Retrying with restored budgets produces the same result and final hash as the successful control run. This acceptance concerns native seeded execution and the internal decision/primitive continuations already present; public accepted-input logs, immutable restore payloads and successful session replacement are covered separately in 3.7 below, while complete structured area/walkthrough replay is covered in 3.9 below and the broader conformance runner remains phase 5. Native xorshift streams are not claimed to equal the reference interpreter's MT19937.

## Completed lifecycle and public saves (3.7)

`GameSession` owns a TurnLoop and publishes the opening packet through `opening()`. Its `execute({expected:{epoch,revision},optionId})`, `completeHost`, `options`, `observe`, `exportSave` and `importSave` form the lifecycle boundary. YES?/FINISH choices have session-owned, monotonic decision IDs. While READ is pending, only that decision's options exist; host and terminal states offer none. Stale identities, wrong choices, duplicate completions and malformed requests preserve the last state, revision, input log and request. Only accepted segments advance revision, once. Load/restore/restart increment epoch from the current session, never from disk. Revision remains monotonic across epochs; the source turn's actionSequence resumes its saved value or resets on restart, so correlate public input by epoch/revision.

SAVE requests carry a `primitive-save` envelope captured at the committed suspended SAVE, before its success branch. The host performs storage and acknowledges success/failure/cancel. A successful RESTORE installs the supplied checkpoint, discards the current frames and resumes the saved SAVE as true; a `boundary` save installs the stored fresh READ without replaying output. Failed/cancelled primitives resume source false branches. Restart acknowledgment constructs and starts a fresh GO using the current checkpoint's configured initial seed and limits, resetting game/gates and preserving transport identity monotonicity. QUIT accepts only success and becomes terminal. FINISH failures print the source failure text and publish a fresh decision; successful replacement leaves no FINISH frames behind.

The strict `zxr-save-v1` envelope contains the adapter ABI, semantic build hash, checkpoint kind, full TurnLoop/Interpreter memory/frames/tasks/operands/loop cursors, RNG state/request position/replay identity, knowledge and transport metadata. The current bundle declares no knowledge rules, so knowledge is exactly `[]`; invented gates are rejected until a future version defines them. Schema validation, interpreter continuation validation and kind/boundary checks happen before installation. Wrong builds, invalid memory/RNG/frames, standalone diagnostic routines, unstarted snapshots and non-SAVE primitive snapshots cannot become public saves. `schema/save.schema.json` publishes this schema; `schemas:check` verifies it against its source and compiles it independently with AJV.

Boundary export/import require ordinary input. `importSave` returns an execution packet so a primitive-save import's resumed success text is delivered to the caller; a boundary import emits no text. The semantic `stateHash()` covers the interpreter, knowledge and terminal bit, excluding transport epoch/revision, operation IDs, source actionSequence and log. Therefore importing the same boundary in a new epoch preserves semantic equality. Source execution remains atomic per segment: GameSession stages a restored loop, prepares the next request and returned packet, then installs everything together. Errors leave published prompts, pending IDs and any externally written SAVE intact; continued decision/host segments retain the command budget.

`acceptedInputs()` returns owned typed records for actions/decisions, host outcomes and imports. Successful restore/import records embed an owned save plus its content hash. `GameSession.replay(game, initialOptions, log)` reconstructs the run without consulting a save store, checking every accepted entry and payload hash. Initial seed/limits, integration catalogue and optional oracle tape must match. The conformance tape remains a diagnostic RNG source, not a replacement for the native accepted-input log or a claim of complete branching multi-restore oracle acceptance (phase 5).

Normal options are deliberately limited to a caller-supplied **trusted integration catalogue** (`actions: [{action,label}]`), empty by default. It supplies stable shared-encoder IDs and cannot accept arbitrary action IDs. It is not a player-facing scope/knowledge option generator: phase 4 must supply available options before a UI uses this interface. `observe()` currently exposes lifecycle state, epoch/revision and moves only, with no raw world, random draws or undisclosed presentation events. Full PlayerObservation, event generation and dynamic normal options remain phase 4.

Twenty-one lifecycle acceptance tests cover original opening, decline quit/restart, acknowledged restart, all host failures/cancellation, terminal quit, boundary and primitive saves, FINISH through the actual victory routine with failed and successful restore/restart, death/resurrection/score/moves, stale IDs and pre-load requests, malformed payloads, owned snapshots/logs, independent schema validation, store-free replay and segment-budget rollback. Exact original-story text comparisons include FINISH failure, saved SAVE restoration and victory; existing clock acceptance continues to cover timed deaths. A failed acknowledged restart also preserves the pending session and reports its prior moves/action sequence rather than the discarded fresh GO state.

Validation: 452 tests across 33 files pass, with typecheck/headless boundaries and production build. All fourteen compiler/reference audits pass, including the published save schema, all 75 original fixtures reproduced twice, and the five-room output check. ## Completed debug API and source traces (3.8)

`src/engine/testing.ts` is the explicit test/developer-tool entry point. `createDebugSession(game, sessionOptions, traceOptions)` returns the normal `session` plus a separate `debug` handle with `stateDump()`, `revealAll()`, `trace()` and `clearTrace()`. Equivalent factories support standalone Interpreter and TurnLoop fixtures. No reveal-all or trace flag is accepted through player requests or JSON saves, and none of these factories/capabilities is exported by `src/engine/index.ts`. The build's boundary checker now scans all production TypeScript source and rejects imports/re-exports of the testing entry point; diagnostic symbols are restricted to the instrumented engine modules. Tests and Node-side developer tools can explicitly import the testing module. These are application boundaries, not a security sandbox for someone with source-code access.

```ts
import { createDebugSession } from '../src/engine/testing.ts';

// reviewedActions is the same trusted integration catalogue used by normal sessions.
const { session, debug } = createDebugSession(
  game, { seed: 37, actions: reviewedActions },
  { maxEntries: 4096, maxAttempts: 4 },
);
debug.clearTrace();               // discard startup diagnostics
const result = session.execute(request);
const attempt = debug.trace().attempts.at(-1);
const dump = debug.stateDump();   // diagnostic data, never a public save envelope
```

The session dump includes its complete TurnLoop/Interpreter checkpoint (memory, frames, locals, operand/task stacks, limits, consumed budgets and RNG state/request cursor), semantic hash, knowledge, lifecycle state, epoch/revision, pending decision/host request, next request identity and accepted-input log. It also decodes named globals as unsigned and signed words, and all 251 objects/rooms with their current parent/children/sibling links, numbered/named flags and current property bytes. `revealAll()` exposes this unfiltered world view for tests only, at input, READ pending, host pending or terminal boundaries. It never changes visibility flags, gate knowledge or available player options. All returned data are owned JSON-safe snapshots; querying or mutating them cannot execute routines or change the live state/RNG/history.

Tracing is disabled for normal sessions. An explicitly instrumented session shares its recorder through staged turn forks, saved SAVE-success continuations, decisions, host failures and restore/restart replacement. Each source execution segment gets a monotonic diagnostic attempt ID, input kind and returned/suspended/error outcome. Entries identify entered commands, bindings, expressions and resumed suspension sites with routine name/ID, execution-program identity, call depth, per-command interpreter step count, exact ZIL file/line/column/offset span, semantic source-map ID, build-local node ID and any macro expansion origins. Commands are recorded when selected for execution, once per entry; repeated loops retain repeated entries and short-circuited/unchosen expressions produce none. Entries describe attempted execution, not committed effects. Parser entry/check/no-verb/not-here fragments retain their program identity and source-map points; replaced parser-middle code is never reported as executed.

The recorder retains the latest 4,096 entries per segment and latest four attempts by default, with explicit dropped-entry/attempt counts. Test tools may set bounds up to 65,536 entries and sixteen attempts. A ring buffer keeps entry retention bounded even in an infinite source loop. Clearing history resets retained data and omission counts without rewinding attempt identities or gameplay. No timer, entropy source, host IO or user callback is involved. Diagnostic traces and counters are excluded from interpreter checkpoints, public saves, semantic hashes, player packets and accepted-input logs.

Failures capture the source fault and current routine stack **before** authoritative state rolls back. This retains the failed path while memory, RNG, frames, output, budgets, pending requests and transport state return to the last exposed boundary. Even a budget exhausted before the first executable expression now has the enclosing routine's source location. A resumed decision failure leaves its committed prompt/decision intact and records a separate failed attempt.
